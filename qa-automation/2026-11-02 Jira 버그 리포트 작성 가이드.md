# Jira 버그 리포트 작성 가이드 (자동 테스트용)

- 작성일: 2026-11-02
- 작성자: Claude Code
- 원본 기준: `../버그리포트/버그리포트-템플릿-가이드.md` (LKM 버그 리포트 템플릿), `../버그리포트/버그리포트-정리.md` (작성된 10건)
- 쓰는 곳: `tools/jira_sync.py bugs` 가 자동 테스트 실패를 Jira 버그로 올릴 때 이 양식으로 본문을 만든다 (`bug_report` 함수). 양식을 바꾸려면 이 문서와 그 함수를 같이 고친다.

## 1. 제목

`[자동] [모듈] 무엇이 — "기대 결과" 아님`

- 템플릿의 제목 기준 `[모듈] 무엇이 + 어떤 조건에서 + 어떻게 잘못되는가`를 따른다.
- `[자동]` = 자동 테스트가 만든 초안 표시. 직접 재현한 뒤 사람이 `[모듈] 현상 요약`으로 다듬는다.
- 예: `[자동] [참가하기] 없는 코드 뒤 재시도 버튼 — "[다시 연결 시도] 버튼 표시 됨" 아님`

## 2. 본문 순서 (템플릿 Full과 같음)

| 순서 | 항목 | 자동으로 채우는 값 | 사람이 할 일 |
|---|---|---|---|
| 1 | 항목 표 — 버그 ID | Jira 이슈 번호 | — |
| | 발견일 | 테스트 실행 날짜 | — |
| | 보고자 | 자동 테스트(Playwright) · 확인: LKM | — |
| | 담당자 | 미할당 | 지정 |
| | 모듈/기능 | TC의 분류 1 / 분류 2 | — |
| | 우선순위 | TC 우선순위로 **제안** (높음 → P2, 보통 → P3, 낮음 → P4) | 재현 후 확정. P1은 블로커일 때 사람이 붙인다 |
| | 심각도 | 미정 | 재현 후 Critical / Major / Minor / Trivial 지정 |
| | 재현율 | 자동 1회 실행 중 1회 실패 (직접 재현 전) | 직접 재현 후 `n/n (%)`로 갱신 |
| | 상태 | 신규 (자동 생성 초안) | 확인중 → 수정중 … |
| 2 | 발생 환경 | 게임 파일과 수정일(빌드 버전), PC · Chromium(Playwright) · 1280×800, OS, 실행 시각 | 실기기 재현이면 기기·OS 추가 |
| 3 | 상세 설명 | 실패한 테스트 이름, 관련 TC 번호, 기획서 근거 | 영향(누가·얼마나 불편한지) 한두 줄 |
| 4 | 사전 조건 | TC의 사전 조건 | — |
| 5 | 재현 스텝 | TC의 테스트 내용 (한 스텝에 한 동작) | 직접 따라 하며 빠진 스텝 보충 |
| 6 | 기대 결과 | TC의 기대 결과 (기획서·TC 근거) | — |
| 7 | 실제 결과 | 테스트 오류 원문 (기대 값·실제 값, 요약하지 않음) | 화면에서 본 현상 한 줄 추가 |
| 8 | 첨부 | 실패 순간 스크린샷 첨부, 관련 TC 이슈 연결(Relates) | 빨간 박스 표시 이미지·영상(타이밍 버그) |
| 9 | 비고 | 확인 체크리스트 + 이 가이드 위치 | 재현 조건·안 되는 조건 |

- 라벨: `auto-qa · 게임 이름 · 초안` (+ 프로젝트에 '버그' 유형이 없으면 `bug`)
- 같은 테스트가 다시 실패하면 새 이슈 대신 **댓글**: "○ 실행에서 다시 실패 (자동 실행 누적 실패 n회)" + 오류 원문. 누적 횟수는 `out/jira_state.json`의 `bug_fails`에 남는다.

## 3. 진행 전 체크리스트 (템플릿 4장 그대로)

- [ ] 제목만 읽고 어떤 이슈인지 알 수 있는가
- [ ] 하나의 리포트에 하나의 버그만 담았는가
- [ ] 재현 스텝을 그대로 따라 했을 때 다시 재현되는가 (직접 1회 재검증) — **안 되면 테스트 코드 문제로 분류하고 닫는다**
- [ ] 빌드 버전·기기·OS가 명시되어 있는가
- [ ] 기대 결과의 근거가 기획서에 있는가 (추측이 아닌가)
- [ ] 에러 메시지를 요약하지 않고 원문 그대로 넣었는가
- [ ] 재현율을 확인했는가
- [ ] 스크린샷 또는 영상이 있는가
- [ ] 이미 등록된 중복 이슈가 아닌가

## 4. 우선순위·심각도

템플릿 3장 표를 그대로 쓴다. 우선순위 = 언제 고칠지(P1~P4), 심각도 = 영향이 얼마나 큰지(Critical~Trivial). 둘을 섞지 않는다.

## 5. 확인 방법

```powershell
python -I tools/jira_sync.py bugs --dry-run   # Jira에 보내지 않고 out/jira_dryrun.json에서 본문 확인
```
