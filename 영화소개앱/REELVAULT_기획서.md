# 🎬 REELVAULT (릴볼트) — 영화 다시보기 정보 사이트 기획서

> 넷플릭스 · 디즈니+ 를 참고한 "영화 정보 + 예고편 + 찜 + 평점" 서비스
> 최종 산출물: `index.html` (단일 파일, 바로 브라우저 실행 가능)

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | **REELVAULT (릴볼트)** — "필름 릴(Reel)을 보관(Vault)한다"는 의미 |
| 컨셉 | OTT 대시보드처럼 영화를 탐색하고, 마음에 드는 작품을 "찜(Vault)"에 보관하는 영화 정보 사이트 |
| 참고 서비스 | Netflix, Disney+ (레이아웃/탐색 UX), TMDB (데이터 원천) |
| 목표 | 실제 영화 API를 연동해 최신/인기/고평점 영화를 탐색하고, 예고편·평점·한줄소개·댓글을 확인할 수 있는 **완결된 프론트엔드 웹앱** 제작 |
| 산출물 형식 | `index.html` 1개 파일 (HTML/CSS/JS 인라인), 기획 문서 `.md` 1개 |

### 왜 "다시보기 사이트"인가
넷플릭스·디즈니+는 스트리밍(재생) 자체가 핵심이지만, 실제 영상 스트리밍 저작권 문제로 인해 본 프로젝트는 **정보형 서비스**로 범위를 좁힙니다.
- ❌ 영화 본편 재생 (저작권 문제로 구현 불가)
- ✅ 영화 정보 탐색, 공식 예고편(YouTube) 시청, 평점/리뷰 확인 — "보기 전 큐레이션" 서비스

## 2. 핵심 기능 명세

### 2.1 메인 화면 (홈)
- **히어로 배너**: 인기 영화 중 1편을 대형 배경(backdrop)으로 노출 + 제목, 한줄소개, "예고편 보기" / "찜하기" 버튼
- **가로 스크롤 랙(Row)**
  - 🔥 지금 인기 있는 영화 (`popular`)
  - ⭐ 평점 높은 영화 (`top_rated`)
  - 🎬 최신 개봉작 (`now_playing`)
- 각 랙은 넷플릭스식 가로 스크롤 카드 리스트

### 2.2 검색
- 상단 검색창에 영화 제목 입력 → TMDB `search/movie` 실시간(디바운스) 검색
- 검색 결과는 그리드로 전환 표시

### 2.3 필터 & 정렬
- **장르 필터**: TMDB 장르 목록 API로 동적 생성 (액션/코미디/로맨스 등 다중 선택 가능)
- **정렬 기준**: 인기순 / 평점순 / 최신순
- 필터·정렬은 `discover/movie` 조합 쿼리로 구현
- **최신순 정렬 규칙 (v3.1 개선)**: 최신순은 "이미 개봉한 영화"를 개봉일 내림차순으로 먼저 보여주고, **개봉 예정작은 목록 맨 뒤로** 보낸다.
  - 서버 쿼리: 개봉작은 `primary_release_date.lte=오늘` + 내림차순, 개봉 예정작은 `primary_release_date.gte=내일` + 오름차순(임박한 순)으로 분리 조회 후 이어 붙임
  - 검색 결과의 클라이언트 정렬에도 동일 규칙 적용

### 2.4 영화 상세 (모달)
영화 카드를 클릭하면 모달 팝업으로 아래 정보만 표시(요청사항 반영, 불필요한 정보 배제):
1. **예고편** — YouTube 공식 트레일러 임베드 (TMDB `videos` API)
2. **한줄 소개** — TMDB `overview`를 활용한 짧은 소개 문구
3. **평점** — TMDB 평균 평점(별점 변환 표시) + 투표 수
4. **댓글(리뷰)** — 사용자가 직접 별점과 코멘트를 남기는 로컬 댓글 기능 (작성/목록/삭제)

### 2.5 찜하기 (내가 보관한 릴)
- 카드/모달에서 하트(♡) 버튼으로 찜 추가·해제
- 상단 네비게이션의 "내 보관함" 메뉴에서 찜한 영화만 모아보기
- `localStorage`에 저장되어 새로고침해도 유지

### 2.6 인기 순위
- "지금 인기 있는 영화" 랙에 1위~N위 랭킹 배지 표시 (마퀴 티켓 스타일 번호)

### 2.7 카테고리 더보기 (v3.1 신규)
- 홈의 3개 랙(인기/평점/최신) 헤더 우측에 **[더보기 ›] 버튼** 배치
- 클릭 시 해당 카테고리의 **전체보기 그리드 화면**으로 전환 (페이지네이션 포함)
- 전체보기 중에도 로고/홈 버튼으로 즉시 홈 복귀 가능

### 2.8 페이지네이션 (v3.1 신규)
- 카테고리 전체보기·검색·필터 결과 그리드에 **페이지 번호 UI** 제공
- **한 페이지당 21편** 노출, 페이지마다 서로 다른 영화 노출
- TMDB API는 페이지당 20편 고정이므로, 필요한 TMDB 페이지(1~2개)를 받아 **21편 단위로 재분할**하는 매핑 계층 구현
  - UI 페이지 N의 시작 인덱스 = `(N-1) × 21` → 대응하는 TMDB 페이지 = `floor(인덱스/20)+1`
- 페이지 버튼 구성: `‹ 1 … (현재±2) … 마지막 ›`, 현재 페이지는 골드 강조
- 상단 카운트에 `총 N편 · 현재/전체 페이지` 표기
- TMDB API 상한(500페이지 = 10,000편)까지만 탐색 가능

## 5. API 연동 계획 — TMDB (The Movie Database)

무료로 발급 가능한 [TMDB](https://www.themoviedb.org/) Open API를 사용합니다. (넷플릭스·왓챠 등 실제 다시보기 서비스들도 참고 데이터로 자주 활용하는 영화 메타데이터 API)

| 목적 | Endpoint |
|---|---|
| 인기 영화 | `GET /movie/popular` |
| 평점 높은 영화 | `GET /movie/top_rated` |
| 최신 개봉작 | `GET /movie/now_playing` |
| 장르 목록 | `GET /genre/movie/list` |
| 필터/정렬 검색 | `GET /discover/movie?with_genres=&sort_by=` |
| 최신순 개봉작/예정작 분리 | `GET /discover/movie?primary_release_date.lte=` / `?primary_release_date.gte=` |
| 텍스트 검색 | `GET /search/movie?query=` |
| 영화 상세 | `GET /movie/{id}` |
| 예고편 영상 | `GET /movie/{id}/videos` |
| 이미지 | `https://image.tmdb.org/t/p/{size}/{path}` |

> ⚠️ **v2 → v3 아키텍처 변경**: 최초 버전은 방문자가 브라우저에 직접 TMDB API Key를 입력해 `localStorage`에 저장하는 방식이었습니다. 이 방식은 **"운영자인 나"에게만 키가 저장**되고, 다른 사람이 배포 링크에 접속하면 그 사람 브라우저에는 키가 없어 매번 새로 입력해야 하는 문제가 있었습니다. 또한 코드에 키를 직접 박아넣으면(하드코딩) 누구나 브라우저 개발자도구로 키를 훔쳐볼 수 있어 위험합니다.
> → 이를 해결하기 위해 **서버리스 프록시(Cloudflare Workers)** 를 두어 TMDB API Key를 서버에만 저장하고, 방문자는 아무것도 입력하지 않아도 되는 구조로 변경했습니다. (아래 6장)

## 6. 서버리스 프록시 아키텍처 (Cloudflare Workers)

### 6.1 구조

```
방문자 브라우저(index.html)
        │  fetch("https://<worker주소>/api/movie/popular?page=1")
        ▼
Cloudflare Worker (server/worker.js)
        │  TMDB_API_KEY(비밀 환경변수)를 붙여서 대신 요청
        ▼
TMDB API (api.themoviedb.org)
```

- 브라우저 코드(`index.html`)에는 TMDB API Key가 **전혀 등장하지 않습니다.**
- Worker는 `/api/...`로 들어온 요청을 그대로 TMDB `/3/...`로 중계하면서, 자신만 아는 `TMDB_API_KEY`를 쿼리에 추가합니다.
- 키는 Cloudflare의 **Secret(환경변수)** 로만 저장되며, 코드나 깃허브에 노출되지 않습니다.

### 6.2 파일 구성 (추가됨)

```
/
├─ REELVAULT_기획서.md
├─ index.html                 ← PROXY_BASE_URL 상수만 바꾸면 됨
└─ server/
   ├─ worker.js               ← 프록시 서버 코드
   └─ wrangler.toml           ← Cloudflare 배포 설정
```

### 6.3 배포 가이드 (사이트 운영자가 딱 한 번만 수행)

1. **TMDB API Key 발급**
   - https://www.themoviedb.org 회원가입 → 프로필 → 설정(Settings) → API
   - "API 키 요청(Create)" → 용도 **개인/교육용(Developer)** 선택 → 키 발급
2. **Cloudflare 계정 준비 (무료)**: https://dash.cloudflare.com 가입
3. **Wrangler CLI 설치**
   ```bash
   npm install -g wrangler
   wrangler login
   ```
4. **`server` 폴더에서 배포**
   ```bash
   cd server
   wrangler secret put TMDB_API_KEY
   # 프롬프트가 뜨면 1번에서 발급받은 TMDB 키를 붙여넣기 (엔터)
   wrangler deploy
   ```
5. 배포가 끝나면 `https://reelvault-proxy.<본인subdomain>.workers.dev` 같은 주소가 출력됩니다.
6. **`index.html` 상단의 아래 줄을 방금 받은 주소로 수정**
   ```js
   const PROXY_BASE_URL = "https://reelvault-proxy.YOUR-SUBDOMAIN.workers.dev";
   ```
7. `index.html`을 다시 배포(호스팅)하면 끝 — 이후 방문자는 **API Key를 몰라도, 입력하지 않아도** 바로 영화 데이터를 볼 수 있습니다.

### 6.4 이 구조의 장단점

| | 내용 |
|---|---|
| ✅ 장점 | TMDB Key가 브라우저에 노출되지 않음 / 방문자는 아무 설정 없이 바로 이용 / Cloudflare Workers 무료 티어(하루 10만 요청)로 충분 |
| ⚠️ 주의 | `index.html`만 여는 정적 배포에서 한 단계 더 나아가 **Worker 배포라는 서버 운영 요소**가 하나 생김 (다만 완전 무료·서버리스라 유지관리 부담은 거의 없음) |
| 🔒 보안 팁 | `server/worker.js`의 `corsHeaders()`에서 `Access-Control-Allow-Origin: "*"`를 실제 배포 도메인으로 좁히면 더 안전합니다 |

### 6.5 index.html이 아직 프록시 없이 켜졌다면?

`PROXY_BASE_URL`이 기본값(`YOUR-SUBDOMAIN` 포함) 그대로면, 방문자가 아닌 **운영자에게만** "프록시 서버가 설정되지 않았습니다" 안내 모달이 뜨도록 만들어 두었습니다. 실제 방문자는 이 화면을 볼 일이 없어야 정상입니다.

## 7. 디자인 컨셉

### 7.1 톤 & 무드
"극장 마퀴(marquee) 조명 + 필름 릴"을 모티프로 한 다크 시네마 테마. 넷플릭스 red/블랙, 디즈니 blue와 겹치지 않도록 **골드(마퀴 조명) + 딥 네이비블랙** 조합 사용.

### 7.2 컬러 토큰
| 이름 | HEX | 용도 |
|---|---|---|
| `--bg` | `#0B0E14` | 배경 (깊은 네이비블랙) |
| `--surface` | `#151A24` | 카드/모달 배경 |
| `--surface-hi` | `#1E2430` | 호버/강조 표면 |
| `--gold` | `#E8B44A` | 마퀴 골드 — 포인트 액션, 랭킹, 로고 |
| `--crimson` | `#D6455A` | 평점/찜 하트, 라이브성 강조 |
| `--text` | `#F5F3EE` | 본문 텍스트 |
| `--muted` | `#8A93A6` | 보조 텍스트 |
| `--line` | `#232838` | 구분선 |

### 7.3 타이포그래피
- **Display**: `Bebas Neue` — 극장 마퀴 간판 느낌의 압축형 서체 (로고, 섹션 타이틀, 히어로 헤드라인)
- **Body**: `Manrope` — 가독성 좋은 지오메트릭 산세리프 (본문, UI 텍스트)
- **Mono/Data**: `Space Mono` — 평점 숫자, 랭킹 번호, 티켓 스텁 느낌의 수치 표기

### 7.4 시그니처 요소
- **필름 스트립 디바이더**: 섹션 사이에 스프로킷 홀(둥근 구멍) 패턴의 필름 릴 라인으로 구분
- **티켓 스텁 랭킹 배지**: 인기 랙의 1~N위 숫자를 영화 티켓 절취선(펀칭) 스타일 배지로 표시
- **호버 시 필름 릴 재생 아이콘**: 카드 호버 시 골드 컬러 플레이 아이콘 페이드인

## 9. 실행 방법

### 9.1 운영자 (최초 1회만)
1. 6장 가이드대로 `server/worker.js`를 Cloudflare Workers에 배포하고 `TMDB_API_KEY` 시크릿 등록

3. `index.html`을 원하는 곳에 호스팅(GitHub Pages, Netlify, Vercel 등 정적 호스팅 어디든 가능)

### 9.2 로컬 테스트 (개발/QA 시)

- 반드시 **`로컬서버실행.bat`** 을 더블클릭해 `http://localhost:8000` 으로 접속해서 테스트합니다. (Python 또는 Node.js 자동 감지)

### 9.3 방문자 (별도 설정 없음)
1. 배포된 링크로 접속 — API Key 입력창이 뜨지 않고 바로 홈 화면 노출
2. 홈 화면에서 인기/평점/최신 영화 탐색, 검색·필터 사용
3. 영화 카드를 클릭해 예고편·평점·한줄소개·댓글 확인
4. 하트 아이콘으로 찜하기 → 상단 "내 보관함"에서 확인 (브라우저별 로컬 저장)

## 12. 트러블슈팅 — 예고편이 보이지 않던 문제 해결

### 12.1 증상
영화 상세 모달에서 예고편이 "등록된 예고편이 없습니다"로 뜨거나, 재생이 되지 않는 영화가 다수 있었습니다.

### 12.2 원인
TMDB의 `/movie/{id}/videos` 조회 시 모든 요청에 `language=ko-KR`을 일괄 적용하고 있었습니다. 그런데 TMDB의 videos API는 **요청 언어와 일치하는 영상만** 반환하기 때문에, 한국어 더빙/자막 예고편이 등록되지 않은 영화(특히 마이너 영화·구작)는 결과가 통째로 비어 "예고편 없음"으로 처리됐습니다.

### 12.3 해결
- `videos` 조회를 **`ko-KR`과 `en-US` 두 언어로 동시에 요청**해 결과를 합치고, 중복은 `key` 기준으로 제거하도록 변경했습니다 (`fetchTrailer()` 함수).
- 트레일러 선정 우선순위: 공식 한국어/영어 Trailer → 공식 아닌 Trailer → Teaser → 그 외 YouTube 영상 순으로 폴백하도록 개선했습니다.
- 그래도 등록된 영상이 아예 없는 영화는 "YouTube에서 검색하기" 링크를 대체로 제공합니다.
- 임베드 플레이어 하단에 "YouTube에서 보기" 원본 링크를 항상 함께 노출해, 저작권사가 임베드 재생을 막아둔 일부 예고편도 시청 경로를 확보했습니다.
- `index.html`을 로컬에서 `file://`로 직접 열면 YouTube 임베드가 브라우저 정책상 제대로 동작하지 않을 수 있습니다. 로컬 테스트 시에는 `python3 -m http.server` 등 간단한 로컬 서버를 띄워 `http://localhost:8000`으로 접속하거나, 실제 배포(GitHub Pages 등) 후 확인하는 것을 권장합니다.

### 12.4 오류 153 "영상 플레이어 구성 오류" & 자동 재생 (v3.2)

#### 증상
영화 카드를 클릭하면 예고편 플레이어는 뜨지만 **"오류 153 — 영상 플레이어 구성 오류"** 가 표시되며 재생(자동 재생 포함)이 되지 않았습니다.

#### 원인
- YouTube는 임베드 요청에 **Referer 헤더(어느 사이트에서 임베드했는지)가 없으면 재생을 차단**하고 오류 153을 반환합니다.
- `index.html`을 탐색기에서 더블클릭해 `file://` 프로토콜로 열면 브라우저가 Referer/Origin을 보낼 수 없어(null) 이 차단에 걸립니다.
- 즉 **API 키나 추가 API의 문제가 아니라, 실행 방식(file:// 직접 열기)의 문제**입니다.

#### 해결
1. **로컬 서버 실행 파일 제공**: `로컬서버실행.bat` 더블클릭 → Python 또는 Node.js(내장 모듈만 사용하는 `local-server.js`) 중 설치된 것으로 `http://localhost:8000` 서버를 자동 실행 + 브라우저 자동 오픈. http로 접속하면 Referer가 정상 전송되어 오류 153이 사라집니다.
2. **file:// 감지 안내 배너**: `file://`로 연 상태에서 예고편 모달을 열면 플레이어 상단에 "로컬서버실행.bat을 실행하세요" 경고 배너를 표시해 사용자가 원인을 바로 알 수 있게 했습니다.
3. **자동 재생**: 임베드 URL에 `autoplay=1` 파라미터 추가 — 카드 클릭(사용자 제스처) 직후 모달이 열리므로 브라우저 자동 재생 정책을 통과합니다. 브라우저가 소리 있는 자동 재생을 막는 환경에서는 YouTube가 **음소거 상태로 자동 재생**을 시작합니다. (별도 API 불필요, `iframe allow="autoplay"` 속성으로 권한 위임)

### 12.5 예고편 재생 차단 추가 개선 (v3.1)
언어 병합으로 "예고편 없음" 오탐은 해결했지만, 예고편이 뜨더라도 **재생 버튼을 눌러도 재생되지 않는** 사례가 남아 있었습니다.
- **원인**: `youtube.com/embed`는 서드파티 쿠키를 사용하므로 시크릿 모드, 브라우저의 강화된 추적 방지(ETP), 일부 확장 프로그램 환경에서 임베드 재생이 차단될 수 있습니다.
- **해결**:
  - 임베드 도메인을 쿠키 없는 전용 도메인 **`youtube-nocookie.com`** 으로 교체
  - `playsinline=1` 파라미터 추가 (모바일 인라인 재생 허용)
  - 저작권사가 임베드 자체를 금지한 영상 대비용 "YouTube에서 보기" 원본 링크는 기존대로 유지

## 14. v3.3 보안 개선 — API 키를 코드에서 분리 (.env)

**작업일: 2026-07-12**

| 항목 | 내용 |
|---|---|
| 문제 | `index.html` 상단에 TMDB API 키가 하드코딩되어 있어, GitHub에 푸시하면 키가 그대로 공개됨 |
| 해결 | 키를 프로젝트 폴더의 **`.env` 파일**(`TMDB_API_KEY=...`)로 이동. `local-server.js`가 `.env`를 읽어 가상 파일 **`/env.js`**(`window.__ENV__`)로 브라우저에 주입하고, `index.html`은 `window.__ENV__.TMDB_API_KEY`를 참조 |
| 보호 장치 | `.gitignore`에 `.env` / `.env.*` 등록(단 `.env.example`은 예외로 커밋), 로컬 서버에서 `.env` 파일 직접 요청은 403 차단 |
| 신규 파일 | `.env`(로컬 전용, git 미포함), `.env.example`(키 없는 템플릿) |
| 실행 방법 | `.env.example`을 `.env`로 복사해 키 입력 → `로컬서버실행.bat` 실행. `.env`가 없으면 기존 키 설정 안내 모달이 표시됨 |
| 주의 | 기존 커밋 히스토리에는 이전 키가 남아 있으므로, TMDB에서 **키 재발급 후 `.env`만 교체**하는 것을 권장 |
