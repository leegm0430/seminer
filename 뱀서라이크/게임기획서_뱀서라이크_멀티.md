## 1. 프로젝트 개요

### 1.1 한 줄 소개
> 친구와 함께 몰려오는 몬스터 무리 속에서 자동 공격 빌드를 쌓아가며 끝까지 생존하는 협동 로그라이트.

### 1.2 핵심 재미 (Core Fun)
- **압도적인 물량과 화면 가득한 이펙트**에서 오는 카타르시스
- 시간이 갈수록 강해지는 나와 몬스터 사이의 **성장 곡선 긴장감**
- 무기/시너지 조합을 골라나가는 **빌드업 전략성**
- 혼자가 아니라 **둘이서 역할을 나누거나 화력을 합쳐 버티는 협동감**

### 1.3 레퍼런스
- Vampire Survivors (핵심 루프, 레벨업 카드 선택)
- Brotato (캐릭터별 개성, 웨이브 구조)
- Risk of Rain 2 (협동 시 난이도 스케일링 방식 참고)

## 2. 왜 "멀티(2인) 협동"인가

프로토타입 단계에서 가장 먼저 검증해야 할 것은 **"협동이 실제로 재미를 배가시키는가, 단순히 어려워지기만 하는가"** 입니다. 이를 위해 아래 요소를 프로토타입에서부터 설계에 반영합니다.

- 몬스터 스폰 수 / 스탯은 **접속 인원 수에 비례해 스케일링** (2인 기준 배율 설계)
- 두 플레이어가 **서로 다른 무기/역할**을 고르도록 유도하는 최소한의 장치 (완전 동일 빌드도 가능하지만, 시너지 보상으로 분업 유도)
- 한 명이 죽어도 즉시 게임오버가 아닌 **다운(Down) → 소생** 시스템으로 협동 텐션 부여
- 부활, 근접 버프 등 **"같이 있을 때 이득"**이 되는 최소 1가지 이상의 메커니즘

## 3. 핵심 게임 루프

```
[스테이지 입장]
      ↓
[가만히 있어도 자동 공격 / 이동으로 회피]
      ↓
[몬스터 처치 → 경험치 오브 획득]
      ↓
[레벨업 → 카드 3장 중 1개 선택 (무기 강화 / 신규 무기 / 패시브)]
      ↓
[시간 경과에 따라 몬스터 물량·강함 증가, 보스 등장]
      ↓
[제한시간(예: 10~15분) 생존 또는 전멸 시 라운드 종료]
      ↓
[결과 정산 → 재도전 / 로비 복귀]
```

> ⚠️ **v0.8 갱신**: 제한시간이 20분으로 확장되고, 보스 등장 시 타이머가 정지하는 **보스 게이트** 구조로 변경되었습니다. 최신 라운드 구조는 §27을 참고하세요.

### 3.1 세션 흐름 (2인 기준)
1. 로비에서 방 생성/코드 입장으로 매칭 (2인)
2. 각자 캐릭터 선택
3. 카운트다운 후 동시 입장, 같은 맵/같은 타이머 공유
4. 몬스터/보스 스폰은 서버(또는 호스트) 권위 기준으로 동기화
5. 라운드 종료 시 결과 화면(생존 시간, 처치 수, 획득 골드 등) 공동 표시

## 4. 캐릭터 & 조작

### 4.1 조작
- 이동: WASD / 방향키 (모바일 확장 시 가상 조이스틱)
- 공격: 자동 (무기가 알아서 발동, 조준은 자동 타겟팅 우선)
- 상호작용: 레벨업 시 카드 선택 (마우스 클릭 or 숫자키)

> ⚠️ **v0.4 갱신**: 웹 프로토타입 개발 과정에서 조작 방식이 아래처럼 변경되었습니다. 최신 조작 방식은 §14를 참고하세요. (자동 공격 → 공격키 입력 시 발사, 자동 타겟팅 → 마우스 조준 방식으로 변경)

### 4.2 프로토타입 캐릭터 (2종)
| 캐릭터 | 컨셉 | 시작 무기 | 특성 |
|---|---|---|---|
| 캐릭터 A | 근접 딜러 | 회전 채찍/검 | 이동속도 소폭 증가 |
| 캐릭터 B | 원거리 딜러 | 마법 투사체 | 공격 사거리 증가 |

> 프로토타입에서는 역할 차별화를 극단적으로 만들지 않고, "같이 하면 커버리지가 넓어진다" 정도의 차이만 둡니다. 소규모 완성작 단계에서 클래스 다양화.

## 5. 무기 & 성장 시스템

### 5.1 레벨업 카드 선택
- 레벨업 시 3장의 카드 제시, 1장 선택
- 카드 종류: **신규 무기 획득 / 보유 무기 강화 / 패시브 아이템**
- 프로토타입 목표: 무기 3~4종, 패시브 3~4종 (조합 시 시너지 1~2개)

### 5.2 프로토타입 무기 예시
| 무기 | 타입 | 효과 |
|---|---|---|
| 채찍 | 근접 광역 | 좌우 반복 타격 |
| 마법탄 | 원거리 단일 | 가장 가까운 적 자동 조준 |
| 오라 | 지속 광역 | 캐릭터 주변 지속 데미지 |

### 5.3 패시브 예시
- 이동속도 증가, 최대 체력 증가, 획득 경험치량 증가, 쿨다운 감소

### 5.4 협동 시너지 (프로토타입 최소 구현)
- 두 플레이어가 **가까이 있을 때** 소량의 공격력/방어력 버프 (근접 협동 유도)
- 서로 다른 무기 보유 시 특정 조합에서 추가 효과 (예: 오라+마법탄 → 오라 안 적에게 마법탄 크리티컬)

## 6. 몬스터 & 난이도

### 6.1 몬스터 구성 (프로토타입)
| 종류 | 특징 |
|---|---|
| 일반 몹 | 단순 직선 추적, 물량 위주 |
| 강화 몹 | 체력/속도 소폭 상승, 소량 스폰 |
| 보스 | 라운드 중반/종반 1회씩 등장, 넓은 공격 패턴 |

### 6.2 난이도 스케일링 (멀티 대응 핵심)
- 몬스터 **스폰 수 = 기본값 × (1 + 0.7 × (인원수-1))** 형태로 완전 비례가 아닌 완만한 증가 (2인이 1인보다 "여유"를 느끼게)
- 몬스터 체력/데미지는 인원수와 무관하게 유지 (물량으로만 난이도 조절 → 밸런싱 단순화)
- 위 수치는 프로토타입 테스트 후 조정 예정

## 7. 멀티플레이 기술 방향 (프로토타입 범위)

> 세부 구현은 개발 단계에서 확정하되, 기획 의도를 아래에 명시합니다.

- **동기화 방식**: 호스트 권위(Host-authoritative) 또는 서버 권위 중 프로토타입은 우선 **호스트 권위 방식**으로 시작 (구현 난이도/개발 속도 우선)
- **동기화 대상**: 플레이어 위치/애니메이션 상태, 몬스터 스폰/위치/HP, 경험치 오브, 레벨업 타이밍
- **비동기 요소**: 카드 선택은 각자 독립적으로 진행 (한 명이 레벨업해도 다른 한 명 게임 진행 멈추지 않음)
- **연결 끊김 처리**: 프로토타입 단계에서는 단순 처리 (재접속 미지원, 이탈 시 솔로 플레이 전환 정도만 고려)
- Unity 진영 후보 기술: Netcode for GameObjects, Mirror, Photon Fusion/Photon PUN (웹 빌드 호환성 기준으로 프로토타입 단계에서 비교 검토 필요)

> ⚠️ 이 섹션은 기획서지만, 기술 스택 선택이 기획(동기화되는 요소 범위, 렉 허용 오차 등)에 직접 영향을 주므로 프로토타입 착수 전 기술 스파이크(짧은 검증)를 권장합니다.

## 12. 웹 플레이 가능 프로토타입 구현 노트 (v0.2 추가)

> `bloodfall_playable.html` — HTML/Canvas 기반 단일 파일로 구현한 1차 플레이 가능 프로토타입. Unity 정식 개발 전, **핵심 루프와 협동 재미를 빠르게 검증**하기 위한 웹 목업이며, 아래 CLAUDE.md 게임 제작 트랙 방식(핵심 동작 우선 → 한 번에 한 기능 확인)을 참고해 정리했습니다.

### 12.1 이 프로토타입의 게임 정의
| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 몰려오는 몬스터를 자동 공격으로 처치하며 레벨업 카드로 성장해, 제한 시간 동안 팀이 함께 버티는 게임 |
| 장르 | 로그라이트 서바이벌 (자동전투) |
| 조작 | P1: WASD 이동(근접 채찍 자동 공격) / P2: 방향키 이동(원거리 마법탄 자동 공격) |
| 목표·점수 | 제한시간(기본 3분) 생존 시 성공, 팀 전원 다운 시 실패. 처치 수·레벨·생존시간으로 결과 집계 |
| 플랫폼 | 웹 브라우저 (HTML/Canvas, 별도 서버 없음) |
| 혼자/여럿 | **로컬 2인 협동** — 한 화면·한 키보드를 나눠 쓰는 방식 (실제 네트워크 멀티플레이 아님) |
| 분위기 | 어둡고 긴장감 있는 고딕 뱀파이어 톤 |

### 12.2 기획서 원안 대비 단순화한 부분
실제 네트워크 통신 없이 브라우저 한 개에서 동작하는 프로토타입이라, 아래 항목은 기획서 원안(§2, §7, §8)과 다르게 단순화했습니다. Unity 정식 개발 시 원안 기준으로 재설계가 필요합니다.

- **멀티플레이 방식**: 서버/호스트 동기화 대신 **로컬 2인 협동**(같은 화면, 키보드 분할)으로 대체. 협동 시너지·다운/부활 등 "재미 검증"에 집중하고, 네트워크 동기화는 별도 기술 스파이크로 분리.
- **레벨업 카드 선택**: 원안은 "본인만 일시정지, 파트너는 계속 진행"이었으나, 한 화면을 공유하는 구조상 카드 선택 중에는 **게임 전체가 일시정지**되도록 단순화. (→ v0.9에서 무정지 레벨업 방식으로 다시 변경, §33)
- **몬스터 종류**: 프로토타입 Must-Have 범위인 구울(일반)·레이스(강화)·블러드 배런(보스) 3종만 구현.
- **난이도 스케일링**: §6.2의 `기본값 × (1 + 0.7 × (인원수-1))` 공식을 스폰 간격에 그대로 적용해 2인 협동 시 약 1.7배 빠르게 몬스터가 등장하도록 구현.

### 12.3 조절 가능한 수치 (CONFIG)
CLAUDE.md 규칙에 따라 모든 밸런스 수치는 파일 상단 `CONFIG` 객체 한곳에 모아뒀습니다. "더 쉽게/어렵게", "라운드 더 길게" 등은 이 값만 바꾸면 됩니다.

## 13. 몬스터 등급 체계 및 보스 특수 패턴 (v0.3 추가)

기존 §6 몬스터 구성을 4개 등급으로 세분화하고, 등급마다 서로 다른 행동 방식을 부여했습니다. 보스는 체력에 따라 페이즈가 바뀌는 다단계 패턴 구조로 확장했습니다.

### 13.1 등급 체계
| 등급 | 몬스터 | 행동 방식 |
|---|---|---|
| 일반 (Common) | 구울 | 단순 추적, 접촉 피해만. 물량 담당 |
| 정예 (Elite) | 레이스 | 평소엔 추적하다가 사거리 안에 들어오면 **예고(붉은 빛) → 빠른 돌진**. 돌진 중 피해 1.6배 |
| 원거리 (Ranged) | 저주술사 (신규) | 플레이어와 일정 거리를 유지하며 접근/후퇴, 사거리 안에서 주기적으로 저주 탄환 발사 |
| 보스 (Boss) | 블러드 배런 | 페이즈제 다단계 패턴 (아래 13.2 참고) |

원거리형(저주술사) 추가로, 기존에는 없던 **"몰려오는 근접 물량 사이로 원거리 견제가 날아오는" 위협 레이어**가 생겼습니다. 등급별 스폰 확률은 생존 시간에 따라 점진적으로 증가합니다.

### 13.2 보스 페이즈 및 특수 패턴
보스는 체력 비율에 따라 페이즈가 전환되며, 페이즈가 낮아질수록 사용 가능한 패턴이 늘어납니다. 모든 특수 패턴은 **예고(telegraph) 후 발동**하는 구조로, 플레이어가 회피할 시간을 줍니다.

| 페이즈 | 체력 비율 | 사용 가능 패턴 |
|---|---|---|
| 1 | 100~60% | 강타, 탄막 |
| 2 | 60~30% | + 소환 |
| 3 (광폭화) | 30% 이하 | + 돌진, 이동속도 1.35배, 패턴 재사용 대기시간 단축 |

- **강타 (Slam)**: 0.8초 예고(확장하는 붉은 원) 후 넓은 범위에 큰 피해
- **탄막 (Burst)**: 0.6초 예고 후 사방으로 10발의 저주탄 발사
- **소환 (Summon)**: 0.5초 예고 후 구울 2마리를 주변에 소환 (2페이즈부터)
- **돌진 (Charge)**: 0.5초 조준 예고(붉은 조준선 표시) 후 빠르게 직선 돌진, 접촉 시 큰 피해 (3페이즈, 광폭화 상태에서만)

### 13.3 설계 의도
- 예고(telegraph) 구조를 모든 특수 패턴에 공통 적용해, 몬스터 수가 아무리 늘어나도 **보스 공격만큼은 "피할 수 있는" 공정한 위협**이 되도록 했습니다.
- 페이즈가 진행될수록 패턴 종류와 속도가 함께 늘어나 **후반부로 갈수록 체감 난이도가 뚜렷하게 상승**하도록 설계했습니다.
- 등급별 위협 방식을 다르게(근접 물량 / 돌진형 / 원거리형 / 보스 패턴) 나눠, 플레이어가 "어디를 먼저 처리할지" 판단하는 재미를 의도했습니다.

## 14. 조작 방식 변경 및 무기 시스템 확장 (v0.4)

플레이 테스트 과정에서 "자동 공격"보다 "직접 조준하고 쏘는" 손맛이 필요하다고 판단해, 조작 방식과 무기 구성을 아래처럼 변경했습니다.

### 14.1 조작 방식 변경
| 구분 | 변경 전 (§4.1 원안) | 변경 후 (v0.4) |
|---|---|---|
| 공격 트리거 | 자동 (쿨다운마다 자동 발동) | **공격키를 누르는 동안에만 발사** |
| 조준 방식 | 자동 타겟팅 (가장 가까운 적) | **P1: 마우스 커서 방향으로 조준** / P2: 마지막 이동 방향 |
| P1 조작 | WASD 이동 | WASD 이동 + **마우스 조준** + Space(공격) |
| P2 조작 | 방향키 이동 | 방향키 이동(이동 방향이 곧 조준 방향) + Enter(공격) |

- 이동과 조준을 분리(P1)해, 이동하면서 다른 방향을 조준하는 트윈스틱 슈터 방식의 조작감을 의도했습니다.
- 로컬 2인 협동 특성상 마우스가 하나뿐이라, P2는 마우스 대신 이동 방향 기반 조준을 유지합니다. Unity 정식 개발 시 네트워크 멀티플레이로 전환되면 각자 자신의 마우스로 조준하게 되므로 이 제약은 자연히 해소됩니다.

### 14.2 기본 무기 통일
- 두 캐릭터의 기본 무기를 **총알(투사체)** 로 통일했습니다. 근접(채찍)/원거리(마법탄) 캐릭터 구분은 레벨업으로 획득하는 **추가 무기**를 통해 유지됩니다.

### 14.3 신규 무기 — 수리검 / 드론
탕탕특공대류 캐주얼 슈터의 "장착형 보조 화기" 컨셉을 참고해 2종을 추가했습니다. 둘 다 **자동 발동**(공격키 불필요)으로, 기본 총알(수동 조준)과 조작 부담을 분담합니다.

| 무기 | 타입 | 효과 |
|---|---|---|
| 수리검 | 근접 지속 | 캐릭터 몸 주위를 도는 투사체가 닿는 적에게 지속 피해. 레벨업 시 개수 증가 |
| 드론 | 원거리 자동 | 캐릭터 주위를 맴돌며 주기적으로 가까운 적을 자동 조준해 사격 |

### 14.4 무기 목록 갱신 (§5.2 대체)
| 무기 | 발동 방식 | 효과 |
|---|---|---|
| 총알 | **수동** (공격키 입력) | 조준 방향으로 발사, 기본 무기 |
| 채찍 | 자동 | 주변 적에게 근접 피해 |
| 오라 | 자동 | 캐릭터 주변 지속 피해 (지속 장판 이미지 표시) |
| 수리검 | 자동 | 몸 주위를 도는 근접 지속 피해 |
| 드론 | 자동 | 주기적 자동 사격 |

> ⚠️ **v0.8 갱신**: 위 무기들은 발동 방식 기준으로 **주무기(수동)/보조무기(자동)** 두 파트로 분리되었습니다. 최신 무기 체계는 §30을 참고하세요.

## 17. 캐릭터 비주얼 재설계 (v0.4)

### 17.1 사람 형태로 재설계
초기 프로토타입의 동글동글한 캐릭터를 **팔다리가 있는 휴먼 실루엣**으로 재설계했습니다. §4.2의 캐릭터 컨셉(근접/원거리)은 유지하되, 시각적으로 "사람이 무기를 들고 있는" 모습을 명확히 표현합니다.

### 17.2 조준 렌더링 방식
캐릭터 전체를 360도 계속 회전시키는 방식은 마우스가 캐릭터의 위/아래를 지날 때 몸이 뒤집혀 보이는 문제가 있어(회전-반전 전환 지점의 시각적 이음매), 아래처럼 구조를 나눴습니다.

- **몸통**: 회전하지 않고, 왼쪽을 바라볼 때만 좌우 반전(2가지 상태) — 항상 똑바로 서 있는 상태 유지
- **무기(총)**: 몸통과 별도로 그려, 조준 방향으로 자유롭게 360도 회전 — 단순한 형태라 회전에 의한 시각적 어색함이 없음

이 구조는 대부분의 탑다운 슈터가 채택하는 표준적인 방식으로, 이후 무기 종류가 늘어나도 같은 원리(몸통 고정 + 무기만 회전)를 재사용할 수 있습니다.

## 18. 실제 P2P 온라인 멀티플레이 구현 (v0.5)

§7에서 "기획 방향"으로만 남겨뒀던 네트워크 멀티플레이를, PeerJS(WebRTC) 기반으로 실제 구현했습니다. §12.2에서 로컬 협동으로 단순화했던 부분을 원안에 더 가깝게 되돌린 것입니다.

### 18.1 구조 — 호스트 권위(Host-authoritative) 방식
§7에서 검토만 하던 방식을 그대로 채택했습니다.
- **호스트**: 몬스터 스폰, 충돌 판정, 보스 AI 등 게임 전체를 계산하는 권위자. 자기 컴퓨터의 WASD+마우스 입력을 직접 읽어 P1을 조작.
- **게스트**: 직접 시뮬레이션하지 않고, **자기 입력(이동/조준 각도/공격 여부)만 초당 약 20회 호스트에 전송**. 호스트가 보내주는 상태 스냅샷(초당 약 20회)을 그대로 화면에 그림.
- 방 코드(4자리)로 연결하며, 신호 교환에는 PeerJS의 무료 공용 브로커 서버를 사용하고, 이후 실제 게임 데이터는 두 브라우저가 직접 주고받는 진짜 P2P(WebRTC DataChannel) 방식입니다.

### 18.2 게스트의 레벨업 카드 선택
§8에서 "카드 선택 시 파트너는 계속 진행"으로 명시했던 원안을 온라인 모드에서 다시 살렸습니다. 게스트가 레벨업하면 호스트가 카드 3장을 생성해 게스트에게 전송하고, 게스트가 직접 골라 응답하면 호스트가 적용합니다. (단, §12.2와 마찬가지로 카드를 고르는 동안 게임 전체는 여전히 일시정지됩니다 — 완전한 비동기 진행은 추후 과제로 남겨둡니다.)

> ⚠️ **v0.9 갱신**: "카드 선택 중 게임 전체 일시정지"는 폐기되었습니다. 레벨업한 플레이어만 무적 상태로 카드를 고르고, 게임과 파트너는 계속 진행됩니다. §33 참고.

### 18.3 한계
- PeerJS 무료 브로커는 STUN만 제공하고 TURN 릴레이가 없어, 양쪽 모두 대칭형 NAT 뒤에 있으면 연결이 실패할 수 있습니다.
- 게스트 화면은 핑만큼 지연되며, 별도의 보간/예측 처리는 없습니다.
- 연결 끊김 후 재접속은 지원하지 않습니다.

## 19. 스테이지 시스템 및 추가 보스 (v0.5)

기존에는 보스가 항상 같은 블러드 배런 1종만 등장했습니다. 라운드를 3개 스테이지로 나누고, 스테이지마다 서로 다른 보스가 등장하도록 확장했습니다.

### 19.1 스테이지 구성
| 스테이지 | 배경 테마 | 등장 보스 |
|---|---|---|
| 1 | 잠긴 묘지 | 블러드 배런 (근접형) |
| 2 | 저주받은 안뜰 | 커스 마더 (원거리·소환형) |
| 3 (최종) | 나이트폴 첨탑 | 나이트폴 공작 (근접+범위 복합형) |

- 라운드 시간을 3등분해 스테이지를 나누고, 각 구간의 90% 지점에서 해당 스테이지의 보스가 등장합니다.
- 스테이지가 바뀌면 배경에 은은한 색조 변화를 줘 분위기 전환을 표현하고, HUD에 "STAGE N · 지역명"을 표시합니다.

> ⚠️ **v0.8 갱신**: 라운드가 20분 4구간(Act) 구조로 재편되며 신규 보스 1종(그레이브 워든)이 추가되어, 스테이지·보스 배치가 §27~§28 기준으로 대체되었습니다.

### 19.2 신규 보스 — 커스 마더 (Curse Mother)
저주술사(§13 원거리 등급)의 상위 개체로, 근접 대신 **거리를 유지하며 압박하는 보스**입니다.
| 페이즈 | 패턴 |
|---|---|
| 1 | 저주 연사 (부채꼴로 5발 연속 발사) |
| 2 | + 저주술사 2마리 소환 |
| 3 (광폭화) | + 독안개(지속 피해 장판을 플레이어 위치에 투하), 순간이동 후 전방위 탄막 |

### 19.3 신규 보스 — 나이트폴 공작 (Duke of Nightfall)
최종 보스로, 블러드 배런의 근접 압박과 커스 마더의 범위 위협을 함께 갖춘 **복합형 보스**입니다.
| 페이즈 | 패턴 |
|---|---|
| 1 | 강타, 레이스 2마리 소환 |
| 2 | + 블러드 레일(조준 방향으로 넓은 직선 범위 공격) |
| 3 (광폭화) | + 돌진, 블러드 레인(맵 곳곳에 시차를 두고 떨어지는 광역 폭격) |

### 19.4 설계 의도
- 같은 보스만 반복되지 않도록 해, 한 판 안에서도 **위협의 성격이 근접 → 원거리 → 복합으로 단계적으로 바뀌는 구조**를 의도했습니다.
- 신규 패턴(독안개, 블러드 레일, 블러드 레인)도 기존 §13.3의 "예고 후 발동" 원칙을 그대로 지켜, 몬스터 수가 아무리 늘어도 보스 공격만큼은 회피 가능하도록 유지했습니다.
- 커스 마더는 거리를 벌리는 특성상 근접 위주 빌드보다 원거리 무기(총알/드론)의 가치를 자연스럽게 높여, 무기 선택에 변화를 주도록 의도했습니다.

## 20. 클리어 조건 변경 — 최종 보스 처치제 (v0.6)

기존엔 라운드 시간(§1의 `ROUND_SECONDS`)이 다 되면 생존 여부와 관계없이 자동으로 "승리" 처리됐습니다. 이를 **최종 보스(나이트폴 공작, §19.3)를 실제로 처치해야만 클리어되는 방식**으로 변경했습니다.

- 시간이 다 돼도 게임이 끝나지 않고, 화면 상단 타이머가 "FINAL"로 바뀌며 빨갛게 펄스 효과가 들어갑니다.
- 최종 보스가 등장한 뒤에는 잡몹 스폰이 멈추고 보스전에만 집중할 수 있습니다.
- 만약 시간이 다 됐는데도 어떤 이유로 최종 보스가 아직 안 나왔다면, 안전장치로 즉시 등장시킵니다.
- 결과 화면 문구도 "생존 성공" → "최종 보스 처치·클리어"로 변경했습니다.

이 변경은 §2에서 세운 "협동 재미 검증"이라는 목표에 더 맞습니다 — 단순히 시간을 버티는 것보다, **팀이 힘을 합쳐 보스를 실제로 쓰러뜨리는 것**이 협동 로그라이트의 핵심 목표에 더 부합한다고 판단했습니다.

> ⚠️ **v0.9 갱신**: "최종 보스 등장 시 잡몹 스폰 중단" 규칙은 폐기되었습니다. 최종 보스전을 포함한 모든 보스전에서 잡몹 스폰이 정상 진행됩니다 (§27.3). 최종 보스 처치 = 클리어라는 조건 자체는 유지됩니다.

## 21. 무기 진화(조합) 시스템 (v0.6)

§5(무기 & 성장 시스템)를 확장해, 뱀서라이크 장르의 핵심 재미 중 하나인 **"무기 조합으로 완전히 다른 무기가 되는" 진화 시스템**을 추가했습니다.

### 21.1 진화 조건
무기를 **최대 레벨(§22 참고)** 까지 강화하고, 지정된 **패시브를 1회 이상 보유**하면 레벨업 카드에서 황금빛으로 빛나는 EVOLUTION 카드가 등장합니다.

| 무기 | 필요 패시브 | 진화 결과 |
|---|---|---|
| 총알 | 질풍의 가호(속도) | **관통탄** — 적을 꿰뚫고 지나감, 피해 1.6배 |
| 채찍 | 불사의 심장(체력) | **심판의 낫** — 범위·피해 증가 + 넉백 |
| 오라 | 탐욕의 시야(획득범위) | **심연의 소용돌이** — 범위 확대 + 적을 끌어당김 |
| 수리검 | 광기의 손놀림(쿨다운) | **칼바람** — 개수 증가, 회전 가속, 판정 범위 확대 |
| 드론 | 질풍의 가호(속도) | **정찰 위성** — 동시 2발 발사, 재장전 단축 |
| 샷건 | 강화장갑(공격력) | **산탄 폭풍** — 탄환 수 증가, 넓은 확산, 피해 증가 |
| 레이저 | 방탄조끼(방어) | **감마 광선** — 광선 폭 확대, 피해 증가 |

### 21.2 설계 의도
- 진화 카드는 일반 카드보다 등장 가중치를 조금 더 줘서, 조건을 충족하면 비교적 빠르게 만나볼 수 있도록 했습니다.
- 패시브를 단순히 "능력치 증가"용으로만 쓰지 않고, **어떤 무기를 키울지에 대한 전략적 선택지**로 연결되게 설계했습니다 (예: 방탄조끼를 고르면 레이저 진화가 열림).

## 22. 탕탕특공대 모티브 신규 콘텐츠 및 최대 레벨 시스템 (v0.6)

캐주얼 슈터 장르(탕탕특공대류)를 참고해 무기·패시브를 확장하고, 무한 강화가 아닌 **뚜렷한 성장 한계**를 두었습니다.

### 22.1 신규 무기
| 무기 | 발동 방식 | 효과 |
|---|---|---|
| 샷건 | 수동(공격키) | 부채꼴로 여러 발 동시 발사, 근거리 버스트 |
| 레이저 | 자동 | 바라보는 방향으로 주기적인 관통 광선 |

샷건·레이저는 **기본 총알을 대체하는 무기**로 설계했습니다. 획득하는 순간 기본 총알은 비활성화되어 더 이상 발사되지 않고, 강화·진화 카드 후보에서도 제외됩니다. (한 캐릭터가 총알+샷건+레이저를 동시에 난사하는 과밀 상태를 방지하기 위함)

> ⚠️ **v0.8 갱신**: "획득 시 대체" 방식은 폐기되었습니다. 총알·샷건·레이저는 **주무기** 파트로 묶여 시작 시 드래프트로 1개만 선택하며, 런 도중에는 레벨업 카드로 등장하지 않습니다. §30~§31 참고.

### 22.2 신규 패시브
| 패시브 | 효과 |
|---|---|
| 방탄조끼 | 받는 피해 감소 |
| 강화장갑 | 전체 무기 피해량 증가 |

### 22.3 최대 레벨 시스템
모든 무기·패시브는 **5레벨(5회)** 을 상한으로 뒀습니다. 카드에도 현재 진행도가 "질풍의 가호 (3/5)"처럼 표시되며, 최대치에 도달한 항목은 카드 풀에서 자동으로 제외됩니다. 무기가 최대 레벨에 도달하면 이후엔 §21의 진화 조건 충족 여부만 확인해 진화 카드로 자연스럽게 이어집니다.

## 25. 맵 확장 및 카메라 시스템 (v0.7)

기존엔 화면(뷰포트) 크기와 실제 플레이 가능 범위가 완전히 같았습니다(900×560). 맵을 **가로/세로 약 3배(2700×1680)** 로 넓히고, 화면은 그 안을 비추는 **카메라**로 바꿨습니다.

### 25.1 카메라 동작 방식
- **로컬 협동**: 같은 화면을 보므로 두 캐릭터의 **중간 지점**을 카메라가 따라갑니다.
- **온라인 모드**: 호스트와 게스트가 각자 다른 화면을 보므로, **각자 자기 캐릭터를 따라가는 카메라**를 씁니다. (팀 동료 위치는 카메라에 영향을 주지 않음)
- 카메라는 즉시 스냅되지 않고 약간의 지연(보간)을 둬서 부드럽게 따라갑니다.
- 맵 가장자리에서는 카메라가 더 이상 밖을 비추지 않도록 경계에서 멈춥니다.

### 25.2 스폰 방식 변경
맵이 커지면서 기존의 "화면 가장자리에서 스폰" 방식은 더 이상 맞지 않아, **플레이어를 기준으로 한 링(고리) 스폰**으로 바꿨습니다. 일반 몬스터는 플레이어 주변 480~580px 거리에서, 보스는 조금 더 가까운 420px 거리에서 등장해 화면 밖에서 다가오는 느낌은 유지하면서도 맵 크기와 무관하게 항상 적절한 거리에서 나타납니다. 보스의 텔레포트·블러드 레인 같은 패턴도 맵 전체가 아니라 **타깃/보스 주변의 한정된 범위**에서만 발동하도록 조정했습니다 (안 그러면 넓은 맵 저편에서 나타나 의미가 없어짐).

## 26. 스테이지 기획 확장 — 배경 장식과 향후 방향 (v0.7)

### 26.1 배경 장식(소품)
넓어진 맵이 휑하지 않도록, 묘비·고사목·가시 기둥 등 **비충돌 배경 장식**을 맵 전역에 흩뿌렸습니다. 플레이어와 부딪히지 않는 순수 연출용이며, 호스트와 게스트가 항상 같은 위치에 같은 장식을 보도록 고정된 시드로 생성됩니다.

### 26.2 현재 한계와 다음 방향
지금은 스테이지 전환이 **시간 기준**으로만 일어나고, 맵은 하나의 연속된 공간이라 "장소를 이동해서 다음 스테이지로 간다"는 느낌은 아직 없습니다. 맵을 키운 김에 다음과 같은 방향을 다음 논의 후보로 남겨둡니다.

- **지역 기반 스테이지**: 맵을 3개 구역으로 나누고, 구역마다 배경 장식·몬스터 구성을 다르게 해 실제로 이동하며 스테이지를 체감하게 하기
- **경로 유도**: 보스가 있는 방향으로 은은한 시각적 단서(빛, 안개 걷힘 등)를 줘서 넓어진 맵에서 방향을 잃지 않게 하기
- **미니맵**: 카메라가 생긴 만큼, 전체 맵에서 내 위치와 아이템 박스·보스 위치를 보여주는 미니맵 UI 검토

## 27. 라운드 시간 확장 및 보스 게이트 시스템 (v0.8)

라운드 시간을 기존 목표치(10~15분, 프로토타입 3분)에서 **20분**으로 확장하고, 시간이 흐르기만 하던 구조를 **보스가 관문(Gate) 역할을 하는 구간(Act) 구조**로 재편했습니다.

### 27.1 타이머 규칙 — 보스 등장 시 정지, 처치 시 재개
- 게임 진행 타이머는 **총 20분(1200초)** 기준으로 흐릅니다.
- 지정된 시각에 보스가 등장하면 **진행 타이머가 즉시 정지**합니다. 보스전이 아무리 길어져도 다음 구간이 침범당하지 않습니다.
- 보스를 처치하면 **타이머가 다시 흐르기 시작**하고, 동시에 다음 구간(Act)으로 전환되며 **신규 몬스터가 스폰 테이블에 해금**됩니다.
- 타이머 정지 중 HUD의 시간 표시는 보스 아이콘과 함께 붉게 점멸해, "지금은 보스를 잡아야 시간이 흐른다"는 규칙을 시각적으로 전달합니다.

### 27.2 구간(Act) 구성 — 20분 / 4구간
| 구간    | 진행 시간         | 배경 테마   | 구간 종료 보스 (타이머 정지)            | 처치 시 해금 몬스터             |
| ----- | ------------- | ------- | ---------------------------- | ----------------------- |
| Act 1 | 00:00 ~ 05:00 | 잠긴 묘지   | 블러드 배런 (근접형)                 | 블러드 배트, 저주술사            |
| Act 2 | 05:00 ~ 10:00 | 무너진 납골당 | **그레이브 워든 (지형 통제형, 신규 §28)** | 시체폭탄병                   |
| Act 3 | 10:00 ~ 15:00 | 저주받은 안뜰 | 커스 마더 (원거리·소환형)              | 무덤지기 골렘, 붉은 각인(정예 변종)   |
| Act 4 | 15:00 ~ 20:00 | 나이트폴 첨탑 | 나이트폴 공작 (최종·복합형)             | — (처치 시 게임 클리어, §20 유지) |

- 기존 §19의 3스테이지 구조는 위 4구간 구조로 대체됩니다. 배경 색조 전환·HUD 지역명 표시(§19.1)와 클리어 조건(§20 최종 보스 처치제)은 그대로 유지됩니다.
- 구간 전환이 **시간이 아니라 보스 처치**에 걸려 있으므로, §26.2에서 지적했던 "스테이지 전환이 시간 기준으로만 일어난다"는 한계가 부분적으로 해소됩니다.

### 27.3 보스전 중 스폰 규칙 (v0.9 개정)
- 보스전 동안에도 **해당 구간의 스폰 테이블(일반·정예·원거리·특수 몬스터 포함)이 정상적으로 유지**됩니다. 보스 패턴과 잡몹 물량을 동시에 상대하는 것이 보스전 난이도의 일부입니다.
- **최종 보스(나이트폴 공작)전도 동일**하게 잡몹 스폰을 정상 진행합니다. §20의 "최종 보스 등장 시 잡몹 스폰 중단" 규칙은 v0.9에서 폐기합니다.
- 시간 기반 난이도 스케일링(스폰 간격 감소 등)만 타이머와 함께 정지합니다. 보스전이 길어져도 물량 압박이 계속 상승하지는 않습니다.
- 보스전 중에도 경험치 수급과 레벨업이 계속 이어지므로, 화력이 부족한 팀도 보스전 도중 성장으로 돌파구를 만들 수 있습니다.

### 27.4 설계 의도
- 기존 구조는 보스를 무시하고 도망만 다녀도 시간이 흘러 다음 구간에 진입할 수 있었습니다. 타이머 정지로 **보스전을 회피 불가능한 필수 관문**으로 만들어, 협동 화력 집중(§2의 핵심 검증 목표)이 매 구간 강제로 발생하게 했습니다.
- 20분 확장으로 성장 곡선(§1.2)이 길어진 만큼, 구간마다 새 몬스터가 해금되어 **후반부가 "같은 적이 더 많이 나오는" 것이 아니라 "다른 성격의 위협이 추가되는"** 방향으로 난이도가 상승합니다.
- 보스전 길이는 팀 화력에 따라 달라지므로, 실제 총 플레이타임은 20분 + 보스전 4회(회당 약 1~2분 목표) = **약 24~28분**을 기준으로 밸런싱합니다.

## 28. 신규 보스 — 그레이브 워든 (v0.8)

Act 2를 담당하는 신규 보스입니다. 블러드 배런(근접 압박)과 커스 마더(원거리 견제) 사이에서 **"움직일 공간 자체를 빼앗는" 지형 통제형**이라는 세 번째 위협 성격을 맡습니다.

### 28.1 페이즈 및 패턴
| 페이즈 | 체력 비율 | 사용 가능 패턴 |
|---|---|---|
| 1 | 100~60% | 사슬 휩쓸기, 뼈감옥 |
| 2 | 60~30% | + 무덤 폭발 |
| 3 (광폭화) | 30% 이하 | + 연쇄 강타, 이동속도 1.3배 |

- **사슬 휩쓸기 (Chain Sweep)**: 0.7초 예고(회전 방향 표시) 후 보스 주변 넓은 원형 범위를 휩쓸어 피해 + 넉백
- **뼈감옥 (Bone Cage)**: 대상 플레이어 주위에 0.8초 예고 후 원형으로 뼈 기둥 링 생성. 기둥은 **일시적 충돌 지형**(약 6초 지속)이며 2~3칸의 틈이 열려 있어 탈출 가능. 갇힌 채 다른 패턴과 겹치는 것이 핵심 위협
- **무덤 폭발 (Grave Burst)**: 플레이어 주변의 배경 묘비 장식(§26.1)이 0.8초 예고 후 폭발해 원형 범위 피해. 순수 연출용이던 배경 소품을 위협으로 재활용
- **연쇄 강타 (Chain Slam)**: 강타(§13.2)를 플레이어 위치를 따라가며 3연속 시전. 한 방향으로 계속 구르지 말고 방향을 꺾어야 회피 가능

### 28.2 설계 의도
- 모든 패턴은 §13.3의 "예고 후 발동" 원칙을 유지합니다.
- 뼈감옥·무덤 폭발은 **이동 공간을 제한하는 위협**이라, 화면을 넓게 쓰며 카이팅하는 기존 공략(§25 맵 확장으로 더 쉬워진)에 제동을 겁니다. 두 플레이어가 서로 다른 뼈감옥에 갇히면 소생(§2)이 늦어지므로, 협동 포지셔닝 판단이 자연스럽게 생깁니다.
- 무덤 폭발은 배경 장식(§26.1)을 재활용하므로 신규 리소스 부담이 적습니다. 단, 온라인 모드에서는 장식이 고정 시드로 동기화되어 있어(§26.1) 호스트·게스트가 같은 묘비 폭발을 보게 됩니다.

## 29. 구간별 신규 몬스터 (v0.8)

§27.2의 구간 해금 구조를 채우는 신규 몬스터 3종 + 정예 변종 1종입니다. 기존 등급 체계(§13.1)에 **신속형/자폭형/탱커형** 세 가지 역할을 추가해, 구간이 넘어갈 때마다 플레이어가 대응 우선순위를 다시 판단하게 만듭니다.

### 29.1 신규 몬스터 목록
| 몬스터 | 역할 | 해금 시점 | 행동 방식 |
|---|---|---|---|
| 블러드 배트 | 신속형 | Act 2 (보스 1 처치) | 체력이 매우 낮지만 빠른 속도로 3~5마리씩 무리 스폰. 지그재그로 접근해 조준을 흔듦 |

### 29.2 설계 의도
- **블러드 배트**: 수동 조준(§14) 체계에서 "빠르고 작은 다수"는 조준 실력을 시험하는 위협입니다. 동시에 보조무기(오라·수리검, §30)가 처리하기 좋은 대상이라, 주무기/보조무기 역할 분담을 체감시킵니다.
- **시체폭탄병**: "예고 중 처치 시 폭발 취소" 규칙으로, 단순 회피가 아니라 **우선 처치 대상 판단**이라는 새 의사결정을 추가합니다. 협동 시 "폭탄병 먼저 잡아줘" 같은 역할 콜이 자연스럽게 발생합니다.
- **무덤지기 골렘**: 후반 물량전에서 화력을 오래 붙잡아 두는 벽 역할입니다. 무시하고 카이팅할 수도 있지만 경험치 대량 드랍으로 처치 동기를 부여해, "잡을까 피할까" 선택지를 만듭니다.
- **붉은 각인**: 신규 리소스 없이 기존 몬스터를 재활용해 최종 구간의 밀도를 높이는 장치로, Brotato류의 정예 변종 방식을 참고했습니다.

## 30. 무기 체계 개편 — 주무기 / 보조무기 분리 (v0.8)

기존에는 총알·샷건·레이저·수리검·드론·오라·채찍이 모두 하나의 "무기" 풀에 섞여 있었고, 샷건·레이저는 획득 시 총알을 대체하는 예외 규칙(§22.1)으로 처리했습니다. 이를 발동 방식 기준으로 **두 파트로 분리**해 예외 없이 일관된 규칙으로 정리했습니다.

### 30.1 분류
| 파트 | 소속 무기 | 발동 방식 | 장착 규칙 |
|---|---|---|---|
| **주무기** | 피스톨, 샷건, 레이저 | 수동 (마우스 조준 + 공격키) | **정확히 1개** — 시작 드래프트(§31)로 선택, 런 내내 유지 |

> 기본 무기 "총알"은 v0.9부터 **피스톨**로 명칭을 변경했습니다. 샷건·레이저와 같은 "화기 이름" 체계로 통일하기 위함이며, 이전 섹션(§14, §21, §22)의 "총알"은 모두 피스톨을 가리킵니다.
| **보조무기** | 채찍, 오라, 수리검, 드론 | 자동 (조작 불필요) | 개수 제한 없음 — 레벨업 카드로 획득·강화 |

- **주무기**: 플레이어가 직접 조준·발사하는 "손맛" 담당(§14의 조작 방식 변경 의도 계승). 런 도중 레벨업 카드에는 **장착한 주무기의 강화/진화 카드만** 등장하고, 다른 주무기는 등장하지 않습니다.
- **보조무기**: 자동 발동되는 빌드 확장 담당. 레벨업 카드에서 신규 획득·강화 모두 가능하며, 4종 전부 모으는 것도 허용합니다.
- 패시브(§5.3, §22.2)는 기존과 동일하게 별도 풀로 유지됩니다.

### 30.2 진화 시스템과의 관계 (§21 갱신)
진화 조건(최대 레벨 + 지정 패시브)은 그대로 두고, 진화 테이블을 파트별로 재분류합니다.

| 파트 | 무기 | 필요 패시브 | 진화 결과 |
|---|---|---|---|
| 주무기 | 피스톨 | 질풍의 가호 | 관통탄 |
| 주무기 | 샷건 | 강화장갑 | 산탄 폭풍 |
| 주무기 | 레이저 | 방탄조끼 | 감마 광선 |
| 보조무기 | 채찍 | 불사의 심장 | 심판의 낫 |
| 보조무기 | 오라 | 탐욕의 시야 | 심연의 소용돌이 |
| 보조무기 | 수리검 | 광기의 손놀림 | 칼바람 |
| 보조무기 | 드론 | 질풍의 가호 | 정찰 위성 |

### 30.3 설계 의도
- 주무기가 1개로 고정되면서 "총알+샷건+레이저 동시 난사" 같은 과밀 상태(§22.1의 우려)가 규칙 차원에서 원천 차단되고, 대체 예외 규칙도 필요 없어졌습니다.
- 주무기는 **런 시작 시의 큰 선택**, 보조무기는 **런 도중의 점진적 빌드업**으로 의사결정의 층위가 나뉩니다. 20분으로 길어진 라운드(§27)에서 카드 풀이 주무기 3종만큼 얇아져, 보조무기·패시브 선택지가 더 자주 등장하는 효과도 있습니다.
- 협동 관점에서는 두 플레이어가 서로 다른 주무기를 고르는 것만으로 역할 차별화(§2)가 시작됩니다.

### 30.4 보조무기 슬롯 제한 — 도입 시점 결정 (v0.9)
슬롯 제한("무엇을 포기할지"의 긴장, Vampire Survivors의 무기 6칸 제한과 같은 원리)은 방향성으로는 채택하되, **보조무기가 4종뿐인 현재 단계에서는 도입하지 않습니다.** 4종 중 3종만 고르는 제한은 긴장감보다 선택지 부족으로 느껴질 가능성이 크기 때문입니다. 보조무기 종류가 6종 이상으로 늘어나는 시점에 슬롯 제한(3~4칸)을 함께 도입하며, 그때 켜기만 하면 되도록 CONFIG 수치 하나로 제어 가능하게 미리 구현해 둡니다.

## 31. 시작 무기 드래프트 & 보스 전리품 카드 (v0.8)

### 31.1 시작 무기 드래프트
게임 시작 직후(카운트다운 전), 각 플레이어에게 **주무기 3종(피스톨/샷건/레이저)이 카드 3장으로 제시**되고 1장을 선택해 시작합니다.

- 레벨업 카드 선택과 동일한 UI를 재사용하되, 카드에 사거리·연사력·범위 특성을 요약 표기해 첫 선택의 근거를 제공합니다.
- 온라인 모드에서는 파트너가 어떤 주무기를 골랐는지 선택 화면에 실시간 표시해, 자연스럽게 조합을 상의하도록 유도합니다 (강제 중복 금지는 두지 않음 — 같은 무기 2개도 유효한 선택).
- 선택 제한시간 10초, 미선택 시 피스톨(표준형) 자동 배정.

### 31.2 보스 전리품 카드 (v0.9 확정)
보스 게이트(§27)와 맞물리는 보상 장치로, **보스 처치 직후 타이머가 재개되기 전에 특별 카드 3장 중 1장을 선택**합니다. v0.8에서 제안했던 3가지 유형 중 "신규 보조무기 즉시 획득"은 제외하고 아래 2가지 유형으로 확정합니다. (보조무기 획득은 레벨업 카드 풀의 고유 역할로 남겨, 전리품 카드가 레벨업의 상위 호환이 되지 않도록 하기 위함)

| 유형 | 내용 |
|---|---|
| 희귀 강화 | 일반 카드보다 상승 폭이 큰 주무기/보조무기 강화 (2레벨 분량) |
| 재정비 | 팀 전원 체력 50% 회복 + 다운된 파트너 즉시 소생 |

- 카드 3장은 **서로 다른 대상의 희귀 강화 2장 + 재정비 1장** 구성으로 제시합니다.
- 보스 처치의 보상을 "타이머 재개"라는 시스템적 결과에만 두지 않고 **즉각적인 성장 보상**으로도 연결해, 구간 종료마다 뚜렷한 리듬(전투 → 보상 → 새 위협)을 만듭니다.
- "재정비" 카드는 다음 구간에 새 몬스터가 해금되는(§27.2) 직전의 회복 창구로, 협동 지속력을 보조합니다.

### 31.3 설계 의도 및 검토했던 대안
- 시작 드래프트는 "레벨업 도중 주무기가 카드 풀을 차지하는" 문제를 없애고, 런의 정체성을 첫 화면에서 결정하게 합니다. 뱀서라이크의 "캐릭터 선택 = 시작 무기 선택" 관습을 카드 UI 하나로 압축한 형태라 추가 구현 부담이 적습니다.
- **검토 후 보류한 대안 — 런 도중 주무기 교체 카드**: 보스 전리품에 "다른 주무기로 교체(레벨 승계)" 카드를 넣는 안도 검토했으나, 주무기별 진화 패시브(§30.2)와 얽혀 빌드가 꼬이기 쉽고 프로토타입 검증 범위를 넘는다고 판단해 보류합니다. 시작 드래프트만으로 충분한지 테스트 후 재논의합니다.
- **검토 후 보류한 대안 — 캐릭터별 주무기 고정**: 캐릭터 컨셉(§4.2)에 주무기를 묶는 안은 캐릭터가 2종뿐인 현재 단계에서 조합 폭을 오히려 줄여 보류합니다. 캐릭터 라인업이 확장되는 단계(§10)에서 "캐릭터 고유 주무기 + 드래프트 혼합" 형태로 재검토합니다.

## 32. 경험치 분배 시스템 (v0.9)

기존에는 경험치 오브를 **직접 주운 플레이어만** 경험치를 얻었습니다. 이 구조는 협동 플레이에서 두 가지 문제를 만듭니다 — 파트너와 같은 지역에서 싸우면 오브를 서로 뺏는 경쟁이 되고, 역할을 나눠 떨어져 싸우면(탱킹/처치 분담 등) 오브 근처에 없던 쪽의 성장이 뒤처집니다.

### 32.1 분배 규칙
- 경험치 오브를 직접 획득한 플레이어: **100%** 획득
- 같은 파티의 다른 플레이어: 거리와 무관하게 **70%** 자동 분배
- "획득 경험치량 증가" 패시브(§5.3)는 **각자 자기가 받는 최종 경험치**에 곱해 적용합니다. (줍는 사람의 패시브가 파트너 분배량까지 불려주지 않음 — 각자의 빌드 선택이 각자의 성장에만 반영)
- 자석 아이템(§16.2)으로 흡수한 오브도 동일한 규칙을 따릅니다.

### 32.2 온라인 동기화
- 호스트 권위(§18.1) 구조에 따라 오브 획득 판정과 경험치 계산은 호스트가 수행하고, 게스트에게는 갱신된 경험치/레벨 상태만 전달합니다. 상태 스냅샷에 이미 경험치 바 동기화(§24)가 포함되어 있어 추가 통신 비용은 거의 없습니다.

### 32.3 설계 의도
- 100%/70% 비대칭을 둔 이유: 완전 균등(100%/100%)이면 오브를 주우러 움직이는 행동 자체가 무의미해지고, 지나치게 낮으면(예: 30%) 결국 오브 경쟁이 됩니다. **"줍는 사람이 약간 이득, 하지만 파트너도 대부분 따라온다"** 수준으로 잡아, 오브 수집의 능동성은 남기면서 역할 분담에 따른 성장 격차를 없앴습니다.
- 팀 전체 관점에서는 오브 1개당 총 170%의 경험치가 생성되므로, 레벨업 속도가 기존 대비 빨라집니다. 20분 라운드(§27)의 성장 곡선에 맞춰 레벨업 필요 경험치 곡선을 재조정하며, 배율(70%)은 CONFIG 수치로 관리합니다.

## 33. 무정지 레벨업 — 무적 카드 선택 (v0.9)

기존에는 한 명이 레벨업하면 **게임 전체가 일시정지**됐습니다(§12.2, §18.2). 레벨업이 잦은 장르 특성상 파트너의 플레이 흐름이 계속 끊기고, 온라인 모드에서는 정지/재개 동기화가 시스템적으로도 부담이었습니다. 이를 **게임은 멈추지 않는 방식**으로 전면 변경합니다.

### 33.1 동작 규칙
1. 플레이어가 레벨업하면 **그 플레이어만 카드 선택 상태**에 들어갑니다. 게임 월드와 파트너는 아무 영향 없이 계속 진행됩니다.
2. 카드 선택 중인 플레이어는 **무적 상태**가 되며, 이동·공격은 불가합니다. 몬스터는 해당 플레이어를 추적 대상에서 제외하고 통과해 지나갑니다. (무적 상태의 플레이어 주변에 몬스터가 쌓여 선택 종료 직후 즉사하는 상황 방지)
3. **선택 제한시간 10초**: 시간 내 선택하지 않으면 카드 중 하나가 **무작위로** 자동 선택되고 즉시 게임에 복귀합니다. (첫 번째 카드 고정이 아닌 무작위인 이유: 자동 선택 결과가 예측 가능하면 "그 카드가 나올 때까지 방치"가 전략이 되므로) 무적을 이용해 위험 구간을 무한정 흘려보내는 악용을 차단하기 위한 장치입니다.
4. 카드 선택 UI 상단에 남은 시간 게이지 바가 표시되어, 급할 때는 빠르게 고르도록 압박합니다.
5. 카드 선택 중에 추가 레벨업이 발생하면(경험치 분배 §32로 발생 가능) 대기열에 쌓이고, 선택 종료 직후 다음 카드 선택이 이어집니다. 각 선택마다 제한시간 10초가 새로 적용됩니다.
6. 무적 시간 동안에도 보조무기(§30)는 자동 발동을 멈춥니다. (무적+자동 화력이 동시에 유지되면 "카드 창을 일부러 늦게 닫는" 것이 이득이 되므로 함께 정지)

### 33.2 모드별 적용
- **온라인 모드**: 게스트 레벨업 시에도 게임은 계속 진행됩니다. 호스트는 게스트의 무적/선택 상태만 관리하고, 10초 타임아웃 판정은 호스트 권위(§18.1)로 처리해 조작 여지를 없앱니다.
- **카드 UI**: 화면 중앙의 **대형 카드 오버레이**(아이콘 + 등급 + 이름 + 설명)로 표시합니다. 배경은 반투명 처리해 뒤에서 계속 진행되는 전투가 보이게 유지합니다. (프로토타입 검증 결과, 측면 축소 표시안은 카드 가독성과 선택 몰입감이 떨어져 중앙 대형 카드안으로 확정)
- **로컬 협동**: 같은 화면을 쓰므로 중앙 오버레이는 **한 번에 한 명만** 사용합니다. 두 명이 동시에 레벨업하면 순서대로 선택하며, 대기 중인 플레이어의 제한시간 10초는 자기 차례가 되어야 흐르기 시작합니다. (대기 중 몰래 시간이 소진되어 무작위 자동 선택되는 일 방지)

### 33.3 설계 의도
- 뱀서라이크의 레벨업은 한 판에 수십 번 발생합니다. 매번 파트너의 게임이 멈추면 **협동이 아니라 서로의 흐름을 방해하는 구조**가 되고, 이는 §2의 "협동이 재미를 배가시키는가" 검증 자체를 오염시킵니다.
- 시스템 관점에서도 일시정지/재개는 온라인 모드에서 타이머·스폰·투사체 상태를 모두 얼렸다 되살려야 하는 동기화 부담이 컸습니다. 무정지 방식은 "플레이어 1명의 상태 플래그"만 동기화하면 되므로 구조가 더 단순합니다.
- 무적(안전 보장) + 10초 제한(악용 차단) + 보조무기 정지(이득 차단)의 세 규칙이 한 세트입니다. 셋 중 하나라도 빠지면 "카드 창 열고 버티기"가 전략이 되므로, 구현 시 반드시 함께 적용해야 합니다. (QA 체크포인트)
