# 스토리게임 제작 키트 — 사용법

설치·서버 필요 없음. 폴더 그대로 두고 `index.html`(플레이어) 또는 `editor.html`(에디터)을 더블클릭해서 브라우저로 열면 됩니다.

## 새로 추가된 기능

- **저장/불러오기(코드 방식)**: 게임 화면 우측 상단에 "저장"/"불러오기" 버튼이 있음. "저장"을 누르면 긴 문자열(저장 코드)이 뜨는데, 이걸 복사해서 메모장 등에 보관하면 됨. 나중에 "불러오기"에 그 코드를 붙여넣으면 그 지점부터 이어서 플레이 가능. (브라우저 자동 저장이 아니라 코드 복사 방식을 쓴 이유는 바로 아래 "언제 내보내기가 필요한가" 항목과 같음 — file://로 열었을 때 브라우저별 저장 공간 처리가 달라 자동 저장을 신뢰할 수 없기 때문.)
- **랜덤 지급**: 에디터의 선택지 "고급 설정"에서 아이템/스킬 지급을 "고정 지급" 대신 "랜덤 지급"으로 바꾸면, 체크한 여러 개 중 하나가 실행할 때마다 무작위로 지급됨(같은 선택지를 여러 번 테스트하면 다른 아이템이 나올 수 있음 — 정상 동작).

## 폴더 구성

```
index.html      ← 완성된 게임을 플레이하는 화면 (학생은 이 파일을 수정하지 않음)
engine.js        ← 진행 로직 (학생은 이 파일을 수정하지 않음)
editor.html      ← 콘텐츠(씬/아이템/스킬/직업/엔딩)를 입력하는 화면 — 학생은 이 파일만 사용
style.css
story-data.js    ← 실제 게임 데이터. editor.html의 "내보내기"로 갱신
images/          ← gameaify로 만든 이미지를 여기에 넣기
videos/          ← Seedance로 만든 영상을 여기에 넣기
```

## 학생 작업 흐름 (매주 반복)

1. `editor.html`을 더블클릭해서 연다.
2. 지난주에 받은 `story-data.js`가 있으면 "가져오기"로 불러온다. (처음이면 생략)
3. 씬 / 아이템 / 스킬 / 직업 / 엔딩 탭에서 내용을 채운다.
4. gameaify에서 만든 이미지를 에디터의 이미지/아이콘 칸에 **끌어다 놓거나(드래그앤드롭)** 클릭해서 선택한다. 파일명이 자동으로 채워지지만, **실제 파일은 이 폴더의 `images`(또는 `videos`) 폴더에 직접 넣어야 한다** — 에디터가 파일을 자동으로 복사해주지는 않는다.
5. "미리보기 열기"를 누르면 화면 오른쪽에 미리보기 패널이 계속 떠 있는다. 편집하다가 확인하고 싶을 때 패널의 "새로고침"만 누르면 되고, **내보내기/가져오기 없이 바로 반영**된다.
6. "링크 검사"로 끊어진 연결/빈 문구가 없는지 확인한다.
7. "내보내기"를 눌러 `story-data.js`를 다운로드하고, 이 폴더의 기존 `story-data.js`를 덮어쓴다.
8. `index.html`을 더블클릭해서 실제로 플레이해본다.

## 꼭 알아둘 것

- **작업 중간중간 "내보내기"를 습관화할 것.** 에디터가 브라우저에 자동 저장(로컬 저장)을 시도하긴 하지만, 브라우저/환경에 따라 파일(file://)에서는 이 자동 저장이 아예 동작하지 않을 수 있다(로컬 저장 접근이 막히는 경우가 실제로 확인됨). 자동 저장을 믿지 말고, 세션이 끝나기 전에 반드시 내보내기 파일을 챙겨야 다음 주(또는 다른 PC)로 이어갈 수 있다.
- 이미지/영상 파일명은 에디터에 입력한 이름과 `images`/`videos` 폴더 안 실제 파일명이 정확히 같아야 한다. 파일 선택 기능은 이름만 자동으로 채워줄 뿐, 파일을 폴더에 넣는 건 수동이다.
- `editor.html`의 "고급(JSON)" 탭은 JSON 문법을 아는 학생만 사용. 잘못 건드리면 "적용" 전까지는 기존 데이터가 안전하니, 적용 전 반드시 확인.

## 언제 "내보내기"가 필요한가

에디터 안의 미리보기 패널은 파일을 건드리지 않고 그 자리에서 바로 확인하는 용도라, **평소 작업/테스트 중에는 내보내기·파일 교체가 전혀 필요 없다.** 아래 두 경우에만 내보내기를 하면 된다.

- 이번 주 작업을 마치고 다음 주(또는 다른 PC)로 이어갈 때
- 진짜 `index.html`(최종 결과물 그대로)을 열어서 확인하거나 제출/공유할 때

에디터(editor.html)와 실제 플레이어(index.html)는 완전히 분리된 파일이라, 파일을 직접 열어 쓰는 이 방식에서는 둘을 실시간으로 자동 연동시키는 건 안전하게 만들기 어렵다(브라우저마다 file://로 열었을 때 저장 공간 공유 방식이 달라서 오작동 가능성이 있음 — 실제로 테스트 중에도 이 문제를 확인함). 그래서 "평소엔 에디터 안 미리보기로 테스트, 마무리할 때만 내보내기" 구조로 설계했다.

## 데이터 형식 요약

`story-data.js`는 `window.STORY_DATA = { ... };` 형태의 JS 파일. 핵심 구조는 `스토리게임_강의설계안.md`의 1.1절 JSON 스키마와 동일 (meta / stats / classes / items / skills / scenes / endings / startScene). 선택지에는 `requires`(조건), `effects`(스탯 증감), `grantItem`/`grantSkill`(획득)을 넣을 수 있음 — 이 4가지는 에디터의 각 선택지 "고급 설정"에서 폼으로 입력 가능하며 JSON을 몰라도 된다.

## 1주차 시연용 샘플

`story-data.js`에는 데모용 짧은 스토리가 이미 들어 있음(직업 선택 → 분기 → 아이템 획득 → 조건부 선택지 → 엔딩까지 전 기능 포함). `images`/`videos` 폴더가 비어 있어서 이미지는 깨져 보이는 게 정상 — 라이브 데모 때 "지금은 이미지가 비어 있죠? gameaify로 채우면 이렇게 됩니다" 식으로 설명하면 자연스러움. 1주차 전에 데모용 이미지를 미리 채워서 완전한 버전으로 시연할지는 현이 정하면 됨.

## 확인 완료된 것 (자동 테스트 통과)

- 에디터: 씬/아이템/스킬/직업/엔딩 추가·삭제, 선택지의 조건/효과/아이템·스킬 지급 설정, 링크 검사, 상시 미리보기 패널(새로고침 클릭 시 즉시 반영, 파일 내보내기 불필요), 내보내기 — 모두 정상 동작 확인
- 씬에 영상을 넣으면 영상이 끝나거나(ended) "건너뛰기"를 누르기 전까지 선택지가 보이지 않도록 처리됨(영상 파일이 깨져 있어도 error 이벤트로 자동 노출되어 막히지 않음)
- 이미지/영상 파일명 입력은 씬 이미지·씬 영상·아이템 아이콘·스킬 아이콘·엔딩 영상 5곳 모두 드래그앤드롭 + 클릭 선택을 지원 (스킬 아이콘에 파일 선택 기능이 빠져 있던 문제 수정함)
- 씬/영상 이미지는 화면 높이의 65%를 넘지 않도록 자동 축소되며 비율이 깨지지 않음 (gameaify의 1:1/16:9/9:16/4:3/3:4 중 어떤 비율을 넣어도 레이아웃이 안 깨짐)
- 플레이어: 직업 선택 → 스탯 보정 반영 → 분기 이동 → 아이템 획득 → 조건부 선택지(아이템 보유/직업) 정상 분기 → 엔딩 도달 → 재시작까지 전체 플로우 정상 동작 확인
- 브라우저 환경별 실제 동작(특히 학교 랩 PC의 Chrome/Edge)까지는 검증하지 못했음 — 1주차 전에 실제 랩 PC 한 대에서 한 번 열어보는 걸 권장
