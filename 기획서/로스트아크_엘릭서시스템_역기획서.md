# 로스트아크 〈엘릭서 시스템〉 역기획서

**문서 성격**: MMORPG 「로스트아크」의 방어구 강화 콘텐츠 〈엘릭서〉를 대상으로 한 역기획서(reverse game design document). 참고하신 SlideShare 원문 *"[역기획] 로스트아크_엘릭서 시스템"*(최지현, wlqhddl97@naver.com, 총 43슬라이드)을 PDF로 확보해 전체 슬라이드를 직접 확인했다. 이 문서는 원본 슬라이드를 그대로 옮긴 것이 아니라, 원본이 취한 목차 구성·분석 방법론(기획 의도를 문제→이유→결과→해결의 인과 구조와 유저 심리 변화로 제시하는 방식, 시스템 규칙·플로우차트·UI 와이어프레임·데이터 테이블 설계까지 포함하는 구성)을 참고하여 내용을 다시 정리하고, 실제 로스트아크 서비스 이력(공식 가이드·확률 공개·업데이트 공지) 조사 결과와 필자의 분석·비교·개선 제안을 더해 새로 작성한 결과물이다.

**추가로 확인된 사실**: 이 원본 역기획서는 엘릭서가 서비스되던 시점에 작성된 자료로 보인다. 그러나 실제 로스트아크의 엘릭서 시스템은 2025년 12월 10일 업데이트로 초월 시스템과 함께 **완전히 삭제**되었고 효과는 장비 기본효과·아크 패시브로 이관되었다(6장 참고). 따라서 이 문서는 "현재도 운영 중인 시스템"이 아니라 "약 2년 10개월간 운영되다 삭제된 시스템"을 다루는 회고적 역기획서로 구성했다.

## 1. 문서 개요

### 1.1 시스템 정의
엘릭서는 신규 레이드 '혼돈의 상아탑' 출시와 함께 선보인 신규 강화 시스템이다. 기존의 '재련'처럼 장착 중인 방어구를 직접 강화하는 방식이 아니라, **별도의 소모품인 '엘릭서'를 먼저 강화한 뒤 그 결과물을 방어구에 부여**하는 2단계 구조를 취한다. 일반 재련과 가장 다른 점은, 플레이어가 강화 결과를 수동적으로 받아들이는 게 아니라 **'정제' 단계에서 강화할 효과 자체를 선택**하고 **'연성' 단계에서 현자의 조언 중 하나를 골라 그 효과를 키워나간다**는 점이다. 즉 로스트아크의 다른 확률형 강화 콘텐츠 대비 유저의 개입 폭이 넓게 설계되어 있다.

### 1.2 시스템 기획 의도

원본 역기획서는 기획 의도를 하나의 목표로 뭉뚱그리지 않고, 세 개의 축으로 나누어 각각을 "문제 → 이유 → 결과 → 해결"의 인과 구조로 제시한다. 이 구조를 그대로 살려 정리하면 다음과 같다.

#### (1) 전략적 선택과 다양성
- **목적**: 다양한 옵션을 제공하는 엘릭서를 통해, 자신이 원하는 효과를 선택해 강화할 수 있는 전략적 재미 요소를 부여한다. 특정 효과가 가진 세트 옵션을 통해 캐릭터 스펙업 방향을 다양화하고, 현자의 조언에 따라 쌓이는 '질서의 힘·혼돈의 힘' 메커니즘으로 매 순간 선택의 무게를 갖게 한다.
- **비교 대상**: 일반 재련은 강화 시도 → 성공/실패라는 단순한 패턴이며, 정해진 옵션의 수치만 상승하는 구조라 별도의 전략이 필요하지 않다. 엘릭서는 플레이어가 자신의 캐릭터에 맞다고 판단하는 효과를 직접 선택해 연성을 진행하므로, 매 선택이 캐릭터 빌드에 영향을 준다.
- **유저 심리(설계자가 기대한 반응)**: "이번 연성에서 첫 번째 조언을 선택하면 질서의 힘이 최대치에 도달하니까 특수한 조언을 볼 수 있겠다!" → "내 캐릭터는 무력화가 부족하니까 무력화를 선택해야겠다!" 처럼, 수치 하나하나를 캐릭터 빌드 관점에서 해석하게 만드는 것이 목표다.

#### (2) 골드 소모 유도
- **문제**: 최종 레이드의 입장 레벨 제한이 1620레벨로 고정되어 있어, 1620레벨 이후의 유저들이 골드를 추가로 소모할 유인이 없었다.
- **이유**: 기존 일반 재련은 강화 단계가 올라갈수록 필요 재화가 기하급수적으로 늘어 비용 대비 효율이 급격히 낮아진다. 이미 최종 레이드 입장 요건을 채운 유저 입장에서는 그 이상 스펙을 올릴 이유를 찾기 어려웠다.
- **결과**: 유저들이 골드를 쓰지 않고 쌓아두기만 하면서 시간이 지날수록 게임 내 골드가 인플레이션되고, 결과적으로 게임 경제 인프라가 무너질 위험이 있었다.
- **해결**: 기존 재련과는 완전히 다른 방식의 신규 강화 시스템(엘릭서)을 구축해, 스펙업 효율을 별도 트랙으로 완화·분산시킴으로써 골드 소모를 자연스럽게 유도하고 경제 활성화를 꾀했다.

#### (3) 콘텐츠 참여 유도
- **문제**: 신규 레이드가 출시된 후 입장 레벨 요건을 채운 유저조차 적극적으로 참여하지 않는 경향이 있었다.
- **이유**: 신규 레이드는 새로운 패턴·기믹을 학습해야 하고, 트라이 과정에서 재도전에 시간이 오래 걸린다. 난이도가 계속 높아지는 반면 이전 레이드 대비 클리어 보상의 차별성은 크지 않았다.
- **결과**: 참여 인원이 줄어들수록 파티 모집 자체가 어려워지는 악순환이 발생한다.
- **해결**: 엘릭서 제작·정제 재료(지혜의 정수, 지혜의 기운 등)를 신규 레이드('혼돈의 상아탑') 클리어 보상으로 연동시켜, 엘릭서를 키우고 싶은 유저가 자연히 레이드에 반복 참여하도록 유도했다.
- **유저 심리**: "레이드 클리어 골드 보상도 별 차이 없으니 참여 안 해야지" → "엘릭서 육성은 꼭 하고 싶으니 레이드에 열심히 참여해야겠다!" → "엘릭서 때문에 반복하다 보니 패턴이 손에 익어서 클리어 타임도 줄었네" 라는 행동 변화 곡선을 의도했다.

## 2. 시스템 규칙

### 2.1 시스템 흐름 (5단계)
1. **연성 촉매 제작**: 정제·연성에 공통으로 쓰이는 소모 재료 '안정된 연성 촉매'를 제작한다.
2. **엘릭서 제작**: 장비에 부여하고자 하는 등급의 엘릭서(예: 선명한 지혜의 엘릭서, 빛나는 지혜의 엘릭서)를 제작한다.
3. **엘릭서 정제**: 엘릭서에 5개의 효과를 부여한다. (2.3 참고)
4. **엘릭서 연성**: 부여된 효과를 강화하기 위해 현자가 건네는 조언을 골라 반복 강화한다. (2.5 참고)
5. **제작 완료**: 연성 기회를 모두 소모하면 엘릭서 연성이 마무리되고, 결과가 방어구에 반영된다.

### 2.2 재료 수급처·사용처 (설계 예시)

| 재료 | 주요 수급처 | 사용처 |
|---|---|---|
| 안정된 연성 촉매 | 제작(재료 소모) | 엘릭서 정제·연성 |
| 지혜의 정수 | 떠돌이 상인(볼다이크 지역), 경매장 | 엘릭서 제작 |
| 빛나는 지혜의 기운 | 혼돈의 상아탑 레이드 클리어 보상 | 엘릭서 제작 |
| 엘릭서(선명한/빛나는) | 위 재료로 제작 | 엘릭서 정제·연성 |

레이드 관문별 보상 수량은 노말/하드 난이도와 관문 순서에 따라 계단식으로 늘어나도록 설계되어 있어(노말 1관문 → 하드 4관문까지 점증), 상위 관문일수록 재료 획득 효율이 높아지는 구조다.

### 2.3 엘릭서 정제 — 상세 규칙
1. 엘릭서를 연성하기 전, 연성할 효과를 선택하는 단계다.
2. 매 차례 3명의 현자가 서로 다른 조언을 건네며, 그중 하나를 선택하면 해당 효과가 슬롯에 부여된다.
3. 효과는 총 5개까지 선택할 수 있으며, 5개를 모두 채우기 전에는 연성 단계로 넘어갈 수 없다.
4. 이미 부여된 효과는 다시 정제할 수 없고, 동일한 효과를 중복 부여할 수도 없다.
5. 정제 1회에는 '안정된 연성 촉매'와 골드가 소모된다.
6. '다른 조언 보기' 버튼으로 현재 3개 조언을 리셋하고 새 조언을 받을 수 있으며, 이 리셋 횟수에는 제한이 있고 정제 완료 후 다음 정제로 남은 횟수가 이월된다.

### 2.4 질서의 힘 / 혼돈의 힘 — 선택 압력 메커니즘
정제·연성 과정에서 제시되는 모든 조언에는 '질서의 힘' 또는 '혼돈의 힘'이 내재되어 있다.
- 플레이어가 **선택한** 조언에는 질서의 힘이 1칸 쌓인다.
- 플레이어가 **선택하지 않은** 나머지 조언에는 혼돈의 힘이 1칸씩 쌓인다.
- 이미 질서의 힘이 쌓인 조언을 다시 선택하면 질서의 힘이 더 쌓이지만, 혼돈의 힘이 쌓여 있던 조언을 선택하면 그 힘이 질서의 힘으로 전환(리셋 후 재적립)된다.
- 어느 한쪽 게이지가 가득 차면 해당 속성의 **특수 조언**이 발동한다. 질서 계열 특수 조언은 "선택한 효과를 봉인 처리"처럼 확정적 방향으로, 혼돈 계열 특수 조언은 "여러 효과의 단계를 무작위로 뒤섞는" 처럼 예측 불가능한 방향으로 설계되어 있다.

이 메커니즘은 "안전하게 같은 선택을 반복할 것인가, 위험을 감수하고 다른 조언을 택해 특수 조언을 노릴 것인가"라는 의사결정 긴장을 매 턴 만들어내는 것이 설계 의도다.

### 2.5 엘릭서 연성 · 추가 연성 · 결과 처리
- 정제 단계에서 확정한 5개 효과를 현자의 조언으로 강화하는 단계. 등급에 따라 최대 레벨이 다르며(예: 선명한 지혜의 엘릭서 4레벨, 빛나는 지혜의 엘릭서 5레벨), 연성 1회에는 촉매와 골드가 소모된다.
- 매 단계 연성이 마무리될 때마다 **'추가 연성'**이 자동 발동해, 무작위 효과 1개의 단계가 추가로 1단계(대성공 시 2단계) 오른다. 추가 연성의 발동 확률·대성공 확률은 직전에 어떤 조언을 선택했는지에 따라 변동한다.
- 연성 가능 횟수를 모두 소모하면 연성이 종료되며, **최종적으로 5개 효과 중 단계가 높은 상위 2개만 결과로 채택**되고 나머지(1단계 미달 효과, 봉인되지 않은 하위 효과)는 소멸한다. 이 "상위 2개만 채택" 규칙이 정제 단계에서의 효과 선택을 더 신중하게 만드는 핵심 장치다.

### 2.6 조언 수치 설계 (예시 발췌)
- **일반 조언**: 선택한 효과 +1단계(확률 분포 예: 25%/50% 등 구간별 차등), 최고단계 효과 -1/-2, 임의 효과 +1단계 등 다양한 조언 유형이 확률적으로 제시된다. 연성 확률·대성공 확률도 "이번 연성에서 선택한 효과 연성 확률 +35%~+70%" 식으로 조언에 따라 변동한다.
- **특수 조언**: 질서(일반) 계열은 "선택한 효과 +1~+2단계, 이번 연성 기회 소모 없이 진행"처럼 이득이 크고, 혼돈(일반) 계열은 "최고 단계 효과를 다른 효과에 무작위로 재분배"처럼 리스크가 크다. 질서(봉인)·혼돈(봉인) 계열은 특정 효과를 강제로 고정하거나 뒤섞는 극단적 결과를 낸다.
- 이처럼 수치 테이블 자체를 "안전 지향 vs 도박 지향"의 두 축으로 세분화한 점이, 이 시스템이 반복 플레이에서도 매번 다른 의사결정을 요구하도록 설계된 근거다.

### 2.7 플로우차트 요약
원본 문서는 정제(15단계)·연성(21단계)의 흐름을 번호가 매겨진 순서도로 각각 제시한다. 핵심만 요약하면:

**정제 플로우**: 대도시 NPC 접촉 → 정제할 엘릭서 선택 → 현자 조언 3개 출력(다른 조언 보기로 리셋 가능) → 조언 선택 → 재료 보유 확인(부족 시 버튼 비활성화) → 부위 전용 효과 선택 시 확인 팝업 → 재료 차감 → 효과 부여 → 5개 효과 완성 시 연성 단계로 전환.

**연성 플로우**: 현자 조언 3개 출력 → 조언 선택(재료 확인 포함) → 강화 효과 적용 → 목표 단계 달성 여부 확인(달성 시 성공 연출) → 추가 연성 진입 → 대성공 여부에 따라 1~2단계 추가 상승 → 연성 횟수 소진 여부 확인 → 남아있으면 반복, 소진되면 결과창 출력.

## 3. UI/UX 설계

원본 문서는 각 화면을 손그림 수준의 와이어프레임으로 제시하고, 번호가 매겨진 UI 요소마다 기능·출력 방식·참조 테이블을 명시하는 방식으로 설계 근거를 남긴다. 핵심 화면과 구성 요소는 다음과 같다.

| 화면 | 번호 요소 | 설계 포인트 |
|---|---|---|
| 엘릭서 목록 | 저장 장소별 필터, 전체/소지품/창고 순 정렬 | 마우스 오버 시 도움말 팝업 노출 |
| 엘릭서 상세 | 엘릭서 아이콘·이름·저장 위치, 남은 연성 횟수 | 등급별 그라데이션 색상 차등(영웅 #7030A0, 전설 #FFC000 등) |
| 목록 스크롤 | 11개 초과 시 스크롤바·스핀 버튼 자동 생성 | 클릭-드래그, 여백 클릭 이동 모두 지원 |
| 효과 목록 버튼 | 마우스 오버 연출, 클릭 시 팝업 | 부위별(공용/투구/상의/하의…) 탭 필터 제공 |
| 장착 장비 팝업 | 장비 아이콘·이름, 부여된 엘릭서 효과 레벨별 수치 | 레벨별 수치는 별도 테이블 참조로 관리 |
| 현자 3인 카드 | 현자 이미지, 조언 텍스트, 질서/혼돈 게이지 | 게이지가 가득 찬 방향으로 특수 조언 발동 |
| 촉매·골드 표시 | 보유량/필요량 분수 표기, 부족 시 버튼 비활성화 | 재료 부족 시 즉시 시각적 피드백 |
| 결과 화면 | 최종 확정된 레벨·효과명·수치 팝업 | 확인 버튼 클릭 시 연성 세션 종료 |

이 설계에서 눈에 띄는 점은 **모든 텍스트·수치가 하드코딩이 아니라 테이블 참조로 관리**되도록 설계되어 있다는 것이다(예: 아이콘은 IconTable, 효과 설명은 StringTable, 수치는 StateDataTable 참조). 이는 로컬라이제이션과 밸런스 패치를 UI 코드 수정 없이 데이터 테이블 갱신만으로 처리할 수 있게 하려는 실무적 설계다.

## 4. 데이터 테이블 설계

원본 문서는 UI 설계를 뒷받침하는 데이터 테이블 스키마를 별도 챕터로 분리해, 실제 개발 조직에 전달 가능한 수준까지 구체화한다. 주요 테이블은 다음과 같다.

| 테이블 | 목적 | 주요 컬럼(예) |
|---|---|---|
| IconTable | 아이콘 이미지 메타데이터 관리 | IconIndex, IconType, IconName, IconInfo, IconPath, IconSize |
| ItemDataTable | 전체 아이템 공통 정보 | ItemIndex, ItemType, ItemName, ItemIcon, ItemGrade, UseProduction/Decomposition/Trade |
| ItemProductionTable | 아이템 제작 레시피 | ItemIndex, Currency1/2_Index·Name·Requirements, UseGold, Gold_Requirements |
| ItemDecompositionTable | 엘릭서 정제/연성 단계별 분해 결과 | ItemIndex, DuctilityStage, Ductility_RemainNum, Currency1/2_Index·Name·DecNum |
| StateDataTable | 엘릭서 효과(스탯) 정의 | StateIndex, StateName, UseDedicateArea, DedicateArea, Level, AbilityValue |
| DuctilityCostTable | 정제·연성 1회당 소모 비용 | DuctilityIndex, ElixirType, DuctilityLevel, Currency1_Requirements, Gold_Requirements |

테이블 간에는 `[테이블명] - [컬럼명]` 형태의 명시적 참조 관계가 정의되어 있어(예: ItemProductionTable의 Currency1_Index가 ItemDataTable의 ItemIndex를 참조), 기획 문서만으로도 실제 스프레드시트/DB 설계에 바로 매핑할 수 있는 수준의 구체성을 갖추고 있다. 이는 포트폴리오용 역기획서가 "그럴듯한 기획 아이디어"에서 그치지 않고 "개발 가능한 데이터 구조"까지 보여주려는 의도로 읽힌다.

## 5. 시스템 개선 제안 (원본 문서 기준)

원본 저자는 스스로 두 가지 문제를 짚고 각각에 대한 개선안을 제시한다.

### 5.1 정제 난이도 문제
- **문제**: 세트 효과를 동반하는 특수 옵션 뽑기의 난이도가 지나치게 높다. 일반 옵션을 제외한 특수 옵션만 총 30개에 달해, 조언에서 특정 특수 옵션이 나타날 가능성 자체가 낮고, 그중에서도 원하는 특수 옵션을 골라야 하므로 체감 난이도가 상당하다.
- **해결 방향 1 — 정제·연성 단계 리롤 횟수 공유**: 현재는 정제·연성 각 단계에서 리롤(다른 조언 보기)이 별도로 관리되는데, 두 단계의 리롤 횟수를 공유하는 구조로 바꾸고 총 횟수를 20에서 1로(원문 표현 기준 총량을 줄이는 방향) 조정해, 남발되지 않으면서도 유저가 더 유리한 시점에 리롤을 몰아 쓸 수 있게 한다.
- **해결 방향 2 — 리롤 재화를 골드로 대체**: 정제 단계에서 조언 리롤에 필요한 재료를 골드로 대체해, 안정적인 연성 촉매 소모 없이도 유저가 더 과감하게 재도전할 수 있게 한다. 플레이어가 원하는 특수 옵션이 나올 때까지 조금 더 부담 없이 시도할 수 있는 여지를 준다.

### 5.2 UI 가시성 문제
- **문제**: 엘릭서 정보를 확인하는 과정에서 가시성이 지나치게 떨어진다. 신규 레이드 파티 모집에는 유저의 스펙(엘릭서 효과) 정보를 확인하는 절차가 사실상 필수인데, 현재 UI로는 이 정보를 확인하려면 여러 단계를 거쳐야 한다.
- **해결 방향 — 새로운 '스펙 정보' 탭 신설**: 캐릭터 정보창에서 스펙을 대략적으로 한눈에 볼 수 있는 전용 탭을 신설해, 유저 편의성을 개선한다. 다만 이 개선안 자체도 "추후 새로운 스펙 요소가 추가될 경우 UI 공간이 부족해질 수 있다"는 한계를 스스로 지적하며, 스크롤 기능 추가나 팝업 창 방식으로의 구조 변경 가능성을 열어둔다.

## 6. 실제 서비스 사례와의 비교 — 라이브 데이터 기반 보강

원본 역기획서가 다루는 메커니즘(정제→연성, 질서/혼돈의 힘, 현자의 조언, 상위 2개 채택 등)은 실제 로스트아크 엘릭서 시스템의 핵심 구조와 상당히 닮아 있다. 다만 실제 라이브 서비스에서는 다음과 같은 차이와 후속 전개가 있었다.

| 항목 | 원본 역기획서 설계 | 실제 라이브 서비스 |
|---|---|---|
| 세트 옵션 명칭 | 미상세(효과 단계 중심 설계) | 달인·회심·강맹(딜러), 선각자·신념(서포터) 등 구체적 세트 옵션명 존재 |
| 목표 수치 | 미상세 | "엘릭서 40"이 사실상 필수 스펙 마일스톤으로 굳어짐 |
| 완화 이력 | (설계 시점 기준 미반영) | 시즌3(2024-07) 패치로 비용 절감·연출 스킵·정제 마지막 옵션 선택권 부여 |
| 최종 결말 | (설계 시점 기준 미반영) | 2025-12-10 시스템 자체 삭제, 아크 패시브로 통합 |

실제 서비스에서는 "정제 난이도가 높다"는 원본 저자의 문제의식이 결국 유저 커뮤니티에서도 동일하게(오히려 더 크게) 제기되었고, 회사 측이 택한 최종 해법은 원본이 제안한 "리롤 공유·골드 대체" 같은 완화책이 아니라 **시스템 자체의 폐지**였다. 이는 확률 기반 강화 콘텐츠에서 "완화"와 "구조적 해결"이 다른 층위의 문제라는 점을 보여주는 실증 사례로 볼 수 있다.

## 7. 회고 및 시사점
1. **의도와 결과의 괴리**: "골드 소모 유도"와 "콘텐츠 참여 유도"라는 설계 의도는 초기에 유효했으나, 확률 구조에 상한이 없다는 점이 장기적으로 피로 누적의 원인이 되어 원래 의도를 배반하는 결과(유저 이탈, 콘텐츠 기피)로 이어졌다.
2. **정교한 설계도 확률 상한 문제를 대체할 수 없다**: 질서/혼돈의 힘, 추가 연성, 상위 2개 채택 등 정교한 하위 메커니즘을 갖추었음에도, "몇 번을 반복해야 원하는 결과가 나오는가"에 상한이 없다는 근본 구조는 유지되었고, 이것이 결국 삭제로 이어졌다.
3. **데이터 테이블까지 설계하는 역기획서의 가치**: 이 원본 문서처럼 UI와 데이터 스키마까지 구체화하면, 포트폴리오 평가자 입장에서 "아이디어 제안자"가 아니라 "실제 협업 가능한 기획자"로 판단할 근거가 늘어난다. 반대로 역기획서를 작성하는 입장에서도, 데이터 구조를 직접 짜보면 원본 시스템의 설계 의도와 한계(예: 상위 2개만 채택하는 규칙이 왜 필요한지)를 더 깊이 이해하게 된다.
