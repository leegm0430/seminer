# 노노그램 P2P 기획서

## 1. 한 줄 정의

가로·세로 힌트 숫자만 보고 격자를 칠해 그림을 복원하는 논리 퍼즐을, 매 판 새로 생성된 문제로 혼자 또는 P2P로 연결된 상대와 함께 푸는 게임이다.

## 2. 게임 규칙

격자의 각 행 왼쪽과 각 열 위쪽에 숫자가 붙어 있다. 숫자는 그 줄에서 연속으로 칠해진 칸 덩어리의 길이를 순서대로 적은 것이고, 덩어리 사이에는 최소 한 칸 이상의 빈칸이 있다. 예를 들어 한 행의 힌트가 `3 1`이면 그 행에는 세 칸짜리 덩어리가 먼저 오고, 한 칸 이상 띄운 뒤 한 칸짜리 덩어리가 온다. 모든 행과 열의 힌트를 동시에 만족시키는 배치를 완성하면 승리다.

승리 판정은 정답 그림과의 일치가 아니라 **힌트 충족 여부**로 한다. 힌트를 모두 만족하는 배치는 정의상 정답이며, 생성기가 유일해를 보장하므로 두 기준은 실제로 같지만, 판정 로직은 힌트 기준으로 구현해 정답 배열을 클라이언트에 노출하지 않아도 되게 한다.

X 표시(빈칸 확정)는 플레이어의 메모일 뿐이며 승리 판정에 관여하지 않는다.

## 3. 퍼즐 생성

매 판 새 퍼즐을 만든다. 서버 없이 P2P 양쪽이 **같은 문제**를 받아야 하므로, 방장이 32비트 시드 하나를 뽑아 상대에게 보내고 양쪽이 같은 결정론적 알고리즘으로 퍼즐을 재생성한다. 그리드 전체를 전송하지 않고 시드 4바이트만 주고받는다.

생성 절차는 다음과 같다.

1. 시드로 Mulberry32 난수기를 초기화한다. 이 난수기는 C#과 JavaScript에서 비트 단위로 동일한 결과를 낸다.
2. 크기별 기준 밀도로 무작위 그림을 만든다. 기준 밀도는 15 이하 0.52, 30 이하 0.58, 그 이상 0.62다.
3. 그림에서 행·열 힌트를 계산한다.
4. 힌트만으로 줄 논리 해법기를 돌린다. 모든 칸이 확정되면 그 퍼즐은 유일해이며 추측 없이 풀린다.
5. 확정되지 않으면 밀도를 0.008 올려 다음 시도로 넘어간다. 최대 120회, 밀도 상한 0.72다.

실측 결과 5×5부터 50×50까지 평균 1~3회 시도 안에 성공하고, 50×50 기준 한 판 생성에 약 22밀리초가 걸린다. 실패로 끝나는 경우는 관측되지 않았다.

줄 논리 해법기는 각 줄에 대해 "이 칸이 채워지는 배치가 존재하는가", "비는 배치가 존재하는가"를 동적 계획법으로 판정한다. 한쪽만 가능하면 그 칸은 확정이다. 행과 열을 번갈아 확정 정보가 더 늘지 않을 때까지 반복한다. 이 방식으로 전부 확정된다는 것은 곧 사람도 추측 없이 풀 수 있다는 뜻이므로, 난이도 보장과 유일해 보장을 한 번에 해결한다.

## 5. 게임 모드

### 5.1 일반 풀이 모드

혼자 푸는 기본 모드다. 시작과 동시에 스톱워치가 올라가고, 완성하면 소요 시간, 실수 횟수, 힌트 사용 횟수, 별점을 보여준다. 크기별 최고 기록을 로컬에 저장해 갱신 여부를 표시한다.

### 5.2 타임어택 모드

제한 시간이 내려가는 모드다. 시간 안에 완성하면 승리, 0이 되면 패배다.

제한 시간은 플레이어가 분 단위로 직접 정한다. 시작 화면에서 타임어택을 고르면 시간 입력칸이 나타나고, 1분에서 600분 사이의 값을 넣을 수 있다. 아무것도 건드리지 않으면 위 표의 크기별 기본값이 그대로 들어가 있고, 직접 넣은 값을 되돌리고 싶으면 크기별 기본값 버튼을 누른다. 맵 크기를 바꿨을 때 직접 정한 값이 없으면 입력칸이 새 크기의 기본값으로 따라 바뀐다. 확인 버튼을 눌렀을 때 잘못 칠한 칸이 있으면 그 칸 하나당 10초씩 차감한다(최대 60초). 잘못 칠한 칸이 없으면 차감하지 않으므로, 확인은 안전한 중간 점검 수단으로 쓸 수 있다. 남은 시간이 점수가 되며, 남은 시간 × 10을 점수로 환산한다.

### 5.3 대전 모드 (먼저 완성하는 쪽 승리)

두 플레이어가 **같은 퍼즐을 각자의 보드에서** 동시에 푼다. 상대 보드의 내용은 보이지 않고, 진행률 막대와 실수 횟수만 실시간으로 보인다. 먼저 힌트를 모두 충족시킨 쪽이 승리한다.

동시 완료 판정은 자기 시계 기준 완료 시각(라운드 시작 시각으로부터의 경과 밀리초)을 서로 보내 더 작은 쪽이 이기는 방식으로 처리한다. 값이 완전히 같으면 방장 승으로 한다. 완료 선언을 받은 쪽은 자기 보드를 검증해 상대의 주장을 확인할 수 있게 완성 스냅샷을 함께 받는다.

한쪽이 나가면 남은 쪽이 부전승 처리되고 그 판은 기록에 남기지 않는다.

### 5.4 협동 모드

두 플레이어가 **하나의 보드를 공유**한다. 모든 칸 입력이 즉시 상대에게 전달되고 양쪽 화면이 같은 상태를 유지한다. 상대의 커서 위치와 최근에 건드린 칸은 상대 색으로 표시해 누가 어디를 하고 있는지 보이게 한다.

같은 칸을 동시에 건드렸을 때는 **타임스탬프가 늦은 입력이 이긴다**. 타임스탬프가 같으면 방장의 입력이 이긴다. 각 입력에는 (플레이어 ID, 논리 시각, 순번)이 붙어 있어 양쪽이 같은 규칙으로 정렬하면 항상 같은 결과에 수렴한다.

되돌리기는 공유 히스토리에 대해 동작하며, 누가 눌렀든 마지막 입력이 취소된다. 협동 모드에서는 되돌리기 요청도 네트워크로 전달된다.

승리는 공동 승리이며, 완성 화면에 각자 칠한 칸 수의 비율을 보여준다.

### 5.5 기간 챌린지

정해진 기간 동안 모두가 같은 문제를 푸는 모드다. 세 종류가 있다.

| 종류 | 크기 | 교체 시점 |
| --- | --- | --- |
| 일간 | 20×20 | 매일 자정(00:00) |
| 주간 | 30×30 | 매주 월요일 자정 |
| 월간 | 50×50 | 매달 1일 자정 |

문제는 **날짜에서 시드를 뽑아** 만든다. 일간은 `D2026-8-21`, 주간은 그 주 월요일 날짜로 `W2026-8-17`, 월간은 `M2026-8` 같은 문자열을 만들고, 그 문자열을 FNV-1a 해시에 섞기를 한 번 더 걸어 32비트 시드로 바꾼다. 같은 기간 안에서는 몇 시에 눌러도 같은 문자열이 나오므로 같은 문제가 나오고, 기간이 넘어가는 순간 문자열이 바뀌어 저절로 새 문제가 된다. 서버에 문제를 저장해 두거나 내려받을 필요가 없다.

같은 계산을 C# 쪽 `ChallengeSeed` 에도 넣어 두었다. 웹 데모와 유니티 빌드가 같은 날 같은 문제를 받는지 확인했고, 세 기간 모두 두 언어의 시드가 정확히 일치한다.

시작 화면의 챌린지 버튼에는 다음 교체까지 남은 시간이 초 단위로 표시되고, 그 기간의 문제를 이미 풀었다면 기록한 시간이 함께 붙는다. 기록은 기간 단위로 따로 저장되므로 기간이 바뀌면 기록도 새로 시작한다. 결과 화면에서 다시하기를 누르면 기간이 끝나기 전까지는 같은 문제를 다시 준다. 초보자 모드로 푼 판은 여기서도 기록에 남기지 않는다.

시간 재기는 일반 풀이 모드와 같은 스톱워치 방식이다.

## 6. 초보자 모드와 확인 버튼

확인 버튼은 현재 보드를 검사하는 기능이다. 힌트를 모두 충족하면 그 자리에서 승리 처리된다.

아직 완성되지 않았을 때 확인이 알려주는 내용은 세 갈래다. **잘못 칠한 칸이 하나도 없으면** 여기까지 맞게 풀고 있다고 알려주고, 앞으로 칠해야 할 칸이 몇 개 남았는지 함께 보여준다. 이 경우는 실수로 세지 않는다. **잘못 칠한 칸이 있으면** 실수 횟수가 올라가는데, 이때 알려주는 정보가 모드에 따라 다르다. 초보자 모드에서는 잘못 칠한 칸이 몇 개인지 개수를 알려주고, 일반 모드에서는 개수조차 알려주지 않고 어딘가 틀렸다는 사실만 알려준다.

어느 경우에도 **틀린 칸의 위치는 표시하지 않는다.** 위치를 짚어 주면 확인 버튼을 반복해 누르는 것만으로 퍼즐이 풀려 버려 논리 퍼즐로서의 재미가 사라지기 때문이다. 위치를 보고 싶은 사람을 위해 설정에 즉시 오류 표시가 있지만, 초보자 모드에서만 동작하고 기본값은 꺼짐이다.

**모드 구분은 확인 버튼을 누른 뒤 되돌리기가 되느냐에 있다.**

초보자 모드가 아닐 때, 확인을 누르면 그 시점의 히스토리에 **확정 장벽**이 세워진다. 되돌리기는 장벽 위쪽 기록까지만 가능하고 장벽을 넘어가지 못한다. 장벽 아래 기록은 폐기되므로 확인 전 상태로는 어떤 방법으로도 돌아갈 수 없다. 확인을 여러 번 누르면 장벽이 그때마다 갱신된다.

초보자 모드에서는 확인을 눌러도 장벽을 세우지 않는다. 히스토리가 그대로 남아 있어 확인 이전 어느 시점으로든 되돌릴 수 있다. 대신 초보자 모드로 푼 기록은 최고 기록에 등록되지 않고, 결과 화면에 초보자 표시가 붙는다.

초보자 모드는 게임 시작 전에만 켜고 끌 수 있다. 판이 진행되는 도중에는 바꿀 수 없으며, P2P 방에서는 방장이 정한 값이 양쪽에 똑같이 적용된다. 한쪽만 되돌리기가 자유로우면 대전이 성립하지 않기 때문이다.

초보자 모드에서만 추가로 제공되는 편의 기능은 다음과 같다. 실수한 칸을 칠하는 즉시 알려주는 즉시 오류 표시, 다음에 확정할 수 있는 칸 한 개를 짚어 주는 힌트 버튼, 그리고 완성된 줄의 힌트 숫자를 자동으로 흐리게 처리하는 기능이다.

## 7. 조작

| 입력 | 동작 |
| --- | --- |
| 좌클릭 | 칠하기 / 칠해진 칸이면 비우기 |
| 우클릭 | X 표시 / X 칸이면 비우기 |
| 드래그 | 처음 누른 칸에서 결정된 동작을 지나가는 칸에 반복 적용 |
| Shift + 드래그 | 직선 방향으로만 적용 |
| 스페이스 | 확인 |
| Ctrl+Z / Ctrl+Y | 되돌리기 / 다시하기 |
| 방향키 | 커서 이동 |
| Enter / Backspace | 커서 칸 칠하기 / X 표시 |
| 마우스 휠 | 위아래 스크롤 (Shift를 누르면 좌우) |
| Ctrl(맥은 Command) + 휠 | 확대·축소 |
| 스크롤 막대 끌기 | 화면 이동 |
| 중간 버튼 드래그, 두 손가락 | 화면 이동 |

드래그 중에는 처음 누른 칸에서 결정된 동작(칠하기 또는 지우기)이 고정된다. 칠해진 칸에서 드래그를 시작하면 지나가는 칸을 전부 지우고, 빈 칸에서 시작하면 전부 칠한다. 한 번의 드래그는 히스토리에서 **한 개의 되돌리기 단위**로 묶인다.

30×30 이상에서는 화면 안에 다 들어가지 않으므로, 판이 화면보다 커지면 오른쪽과 아래에 스크롤 막대가 나타난다. 막대는 손잡이를 끌어도 되고 빈 트랙을 눌러 그 자리로 뛰어도 된다. 휠은 확대가 아니라 스크롤로 동작하고, 확대는 확대 버튼이나 Ctrl+휠로 한다. 힌트 줄은 스크롤해도 화면 가장자리에 붙어 따라온다.

**판의 틀은 확대·축소와 무관하게 항상 같은 자리를 지킨다.** 그리기 영역을 세 구역으로 나누고 각 구역을 잘라내기 때문에, 스크롤로 화면 밖으로 밀려난 줄의 힌트 숫자가 반대편 띠를 침범하거나 칸이 틀 밖으로 삐져나오는 일이 없다. 판이 그려지는 자리, 가로 힌트 띠, 세로 힌트 띠가 서로의 영역을 넘지 못한다.

확대에는 상한이 있다. 칸을 키우면 힌트 띠도 같이 두꺼워져서, 그대로 두면 띠가 화면을 다 덮고 판이 보이지 않게 된다. 그래서 힌트 띠가 화면의 45%를 넘지 않는 선에서 칸 크기의 최대값을 그때그때 계산해 제한한다. 창이 작으면 상한도 함께 내려간다.

| 양쪽 힌트 표시 | 끔 | 반대편 가장자리에도 힌트를 표시 |
| 좌표 표시 | 끔 | 행·열 번호를 가장자리에 표시 |
| 칸 카운터 | 켬 | 칠한 칸 수 / 전체 채워야 할 칸 수 |
| 현재 행·열 강조 | 켬 | 커서가 있는 행과 열을 초록으로 칠하고 그 줄의 힌트 숫자도 초록으로 표시 |
| 완성 줄 자동 X | 켬 | 힌트를 다 채운 줄의 남은 칸을 자동으로 X 처리 |
| 완성 힌트 흐리게 | 켬 | 충족된 힌트 숫자를 흐리게 |
| 5칸 구분선 | 켬 | 5칸마다 굵은 격자선 |
| 드래그 채우기 | 켬 | 끄면 한 칸씩만 입력 |
| 실수 시 진동·소리 | 끔 | 확인에서 오류가 났을 때 피드백 |
| 즉시 오류 표시 | 끔 | 초보자 모드에서만 동작한다. 틀린 칸의 위치를 즉시 표시하므로 기본은 꺼짐 |
| 최근 변경 표시 | 끔 | 마지막 입력 칸에 테두리 |

설정은 로컬에 저장되며 판을 넘어가도 유지된다. 설정은 순수하게 표시 방식에 관한 것이므로 P2P 상대와 동기화하지 않는다. 다만 초보자 모드, 맵 크기, 게임 모드, 타임어택 제한 시간은 규칙에 해당하므로 방장 값이 강제된다.

## 9. 리플레이

모든 입력을 기록해 판이 끝나면 "풀었던 방식"을 다시 보여준다.

기록 단위는 다음과 같다.

| 필드 | 내용 |
| --- | --- |
| t | 라운드 시작으로부터의 경과 밀리초 |
| kind | 입력 종류(칠하기, X, 지우기, 되돌리기, 다시하기, 확인, 힌트) |
| cells | 영향받은 칸 목록(드래그는 여러 칸이 한 항목) |
| by | 입력한 플레이어 ID (협동·대전 모드에서 구분) |

재생 화면은 판을 그대로 다시 보여주되 **가로·세로 힌트 숫자를 함께 그린다.** 숫자 없이 칠해진 칸만 보면 무엇을 왜 그렇게 놓았는지 알 수 없기 때문이다. 재생이 진행되는 동안 힌트가 충족된 줄의 숫자는 흐려지므로 어느 줄이 언제 끝났는지 눈으로 따라갈 수 있고, 방금 들어온 입력의 칸에는 테두리가 쳐져 어디를 건드렸는지 바로 보인다.

진행 막대를 끌어 임의 시점으로 이동할 수 있고, 배속(0.5×, 1×, 2×, 4×, 8×, 즉시)을 고를 수 있다. 되돌리기와 확인은 타임라인에 표식으로 표시되어 어디서 막혔는지 한눈에 보인다. 대전 모드에서는 두 사람의 진행률 곡선을 겹쳐 그려 언제 역전이 있었는지 보여준다.

리플레이는 시드와 입력 목록만으로 완전히 재현되므로 파일 크기가 작다. JSON으로 내보내고 불러올 수 있게 한다.

## 10. P2P 네트워크

### 10.1 연결

시그널링 서버 없이 WebRTC DataChannel을 쓴다. 방장이 만든 초대 코드(압축된 SDP offer)를 상대에게 전달하고, 상대가 만든 응답 코드를 방장이 붙여 넣으면 연결된다. 서버 없이 두 번의 코드 교환으로 직접 연결이 성립한다.

유니티 쪽에서는 같은 프로토콜을 유지한 채 전송 계층만 교체할 수 있도록, 메시지 정의와 전송 수단을 분리해 `INonogramTransport` 인터페이스로 추상화한다.

### 10.2 메시지

| 타입 | 방향 | 내용 |
| --- | --- | --- |
| `HELLO` | 양방향 | 프로토콜 버전, 플레이어 이름, 플레이어 ID |
| `ROOM_CONFIG` | 방장 → 상대 | 모드, 크기, 초보자 여부, 제한 시간 |
| `ROUND_START` | 방장 → 상대 | 시드, 라운드 번호, 시작 시각 |
| `READY` | 상대 → 방장 | 퍼즐 생성 완료 통보 |
| `MOVE` | 양방향 | 순번, 논리 시각, 칸 목록, 상태 |
| `UNDO` / `REDO` | 양방향 | 협동 모드의 공유 히스토리 조작 |
| `PROGRESS` | 양방향 | 진행률, 실수 횟수 (대전 모드, 500ms 간격) |
| `CURSOR` | 양방향 | 커서 좌표 (협동 모드, 100ms 간격) |
| `CHECK` | 양방향 | 확인 버튼 사용 통보 |
| `FINISH` | 양방향 | 완료 시각, 완성 보드 해시 |
| `RESULT` | 방장 → 상대 | 승패 확정 |
| `REMATCH` | 양방향 | 다음 판 요청 |
| `PING` / `PONG` | 양방향 | 지연 측정, 연결 유지 (2초 간격) |

### 10.3 동기화 원칙

퍼즐은 시드로 재생성하므로 판 데이터를 보내지 않는다. 협동 모드의 보드 상태는 입력만 주고받고 각자 재생하며, 충돌은 (논리 시각, 플레이어 ID) 순으로 결정론적으로 해소한다. 30초마다 보드 해시를 교환해 불일치가 감지되면 방장 보드를 기준으로 전체 동기화한다.

연결이 5초 이상 끊기면 재연결 대기 화면을 띄우고, 30초를 넘기면 남은 쪽 부전승 또는 솔로 전환을 제안한다.

## 11. 화면 구성

시작 화면에서 모드, 크기, 초보자 여부를 고르고 혼자 시작하거나 방을 만든다. 방을 만들면 초대 코드가 나오고, 상대가 붙으면 방장이 시작을 누른다.

게임 화면은 가운데 격자, 위와 왼쪽에 힌트, 상단에 타이머·진행률·실수 횟수, 하단에 확인·되돌리기·다시하기·포기·설정 버튼이 놓인다. P2P일 때는 상단 우측에 상대 진행 정보가 붙는다.

결과 화면은 승패, 소요 시간, 실수 횟수, 별점, 완성된 그림, 그리고 리플레이 재생 버튼과 다시하기 버튼으로 구성한다.
